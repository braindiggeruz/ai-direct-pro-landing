# 07 — HAIERSHOP SEO PRESERVATION FRAMEWORK

**Цель:** любые будущие изменения не должны разрушить уже накопленную видимость. Рост трафика за год: +194% кликов (28 дней) и +207% (90 дней). Главный найденный механизм потерь — **смена URL и снятие с публикации без 301** (128 мёртвых URL, 1 802 клика за 12 мес). Поэтому фреймворк построен прежде всего вокруг URL-инвариантов.

## B. SEO INVARIANTS (не должны меняться случайно)

### B1. URL-инварианты (самое важное)
1. **Ни один URL из `11_BASELINE_URL_INVENTORY.csv` с Protection Priority T1/T2 не меняет адрес и не перестаёт отдавать 200.** T1 — 25 URL, T2 — 94 URL.
2. Любая смена `path.alias` у товара, категории или статьи **автоматически** создаёт 301 со старого адреса. До внедрения модуля Redirect (сейчас не обнаружен) смена алиасов **запрещена**.
3. Товары **не снимаются с публикации**. Вместо этого статус «нет в наличии» + блок альтернатив. При окончательном выводе модели — 301 на преемника, иначе на категорию.
4. Статьи блога с кликами за 12 мес не удаляются без 301 на ближайшую по интенту страницу.
5. Языковые префиксы `/uz/` и `/ru/` и язык по умолчанию (UZ) неизменны.

### B2. Индексируемость
- Все T1–T3 URL: `200`, `meta robots` без `noindex`/`unavailable_after`, без `X-Robots-Tag: noindex`.
- robots.txt — без новых `Disallow`, затрагивающих `/uz/` и `/ru/`.

### B3. Canonical
- **Self-canonical на всех коммерческих URL** (сейчас 755/760).
- Canonical никогда не указывает на 404/403 или на другой язык.

### B4. Hreflang
- Взаимность UZ↔RU на 100% страниц (сейчас 760/760).
- Цели hreflang отдают 200.
- `html lang` совпадает с префиксом.

### B5. Внутренние ссылки
- Каждая T1/T2-категория остаётся в главном меню и в хлебных крошках.
- У каждого товара ≥1 входящая ссылка из категории.
- Внутренние ссылки на 404/403 отсутствуют (сейчас 0).

### B6. Главный контент
- Название, цена, описание и характеристики товара присутствуют в исходном HTML (сейчас да: рендер на сервере, Drupal), а не только после JS.

### B7. Корректность товарных данных
- Цена в JSON-LD = видимая цена (сейчас 60/60).
- `availability` = видимый статус.
- Модель в title = H1 = `sku`.
- Нет фиктивных рейтингов и отзывов.
- Политики возврата и доставки в JSON-LD = тексты политик.

## D. STAGING VALIDATION
**Наличие staging неизвестно** (DATA NOT AVAILABLE). Требования к staging:
1. Закрыт от индексации **HTTP-аутентификацией** (предпочтительно) или `X-Robots-Tag: noindex, nofollow` на всех ответах. **Не только robots.txt** — он не предотвращает индексацию по внешним ссылкам.
2. Абсолютные URL в canonical, hreflang и sitemap на staging указывают на staging-хост и никогда не попадают в production. Обратное тоже: production-шаблоны не содержат staging-хоста.
3. Отдельный GA4-поток или отключённая аналитика.
4. Прогон чек-листа C целиком на staging с теми же 20 эталонными URL.
5. Перед выкаткой — grep собранного HTML на staging-хост и на `noindex`.

## E. LIMITED ROLLOUT
| Тип изменения | Пилот | Длительность наблюдения | Критерий расширения |
|---|---|---|---|
| Title / description категорий (YELLOW) | 2–3 **не-T1** категории одного языка, уровня T2, например `/ru/kulery-dlya-vody`, `/uz/suv-kulerlar`, `/uz/idish-yuvish-mashinalar` | ≥28 дней в одном сезоне | CTR ↑ без падения позиции (> 0.5) и кликов против контроля |
| H1 категорий (YELLOW) | 2 категории | ≥28 дней | то же |
| Шаблон JSON-LD (YELLOW) | выкатывается на все сразу (шаблон), валидация на 5 URL | 7–14 дней | Enhancements без новых ошибок, PRODUCT_SNIPPETS стабильны |
| Контент категорий и товаров (GREEN) | партии по 5–10 URL | 28 дней | нет падения по запросам страницы |
| Перелинковка блог → категории (YELLOW) | 5–10 статей одного кластера | 28 дней | рост показов категории по целевым запросам, без потерь статьи |
| 301 для мёртвых URL (YELLOW) | партия 10 URL с наибольшими кликами | 14 дней | 301→200, рост показов на целевых URL |

Контрольная группа — сопоставимые страницы без изменений.

| Изменение | Откат | Время |
|---|---|---|
| Метатеги (модуль metatag) | вернуть значения из снимка JSON:API (`metatag`, `field_meta_tegi`) | минуты |

## G. POST-CHANGE MONITORING
| Метрика | Источник | Когда смотреть |
|---|---|---|
| Статусы и canonical 20 эталонных URL | GET-скрипт | в день релиза, D+1, D+7 |
| 404 и 403 в логах сервера и GSC (Not found / Blocked 403) | GSC Pages, логи | D+1, D+7, D+28 |
| Клики и показы T1/T2 URL (28 дней против того же окна прошлого года и против предрелизного окна) | GSC | D+7 (ранний сигнал), D+28 (вывод) |
| Позиции по топ-50 запросам (query×page) | GSC | D+14, D+28 |
| Product snippets / Merchant listings: ошибки и предупреждения | GSC Enhancements | D+7, D+14 |
| PRODUCT_SNIPPETS: клики и CTR | GSC searchAppearance | D+28 |
| Organic key events (click_tg, click_tel, zvonok, order) и ecommerce (после внедрения) | GA4 | D+28 |
| CWV p75 | GSC CWV / CrUX | D+28 (полевые данные запаздывают) |

**О причинности.** Позиции и трафик реагируют с задержкой (дни–недели) и подвержены сезонности (пик кондиционеров в июле, отопления — с октября). Краткосрочный сдвиг **не доказывает** эффект изменения. Вывод делается по окну ≥28 дней против контрольной группы и того же сезона прошлого года.

## H. SEO REGRESSION ALERTS (пороги для ручной проверки)
| Сигнал | Порог |
|---|---|
| Любой T1/T2 URL отдаёт ≠200 или изменил canonical/robots | **немедленно** (P0) |
| Новые URL в GSC «Not found (404)» или «Blocked (403)» с кликами за 12 мес | ≥1 → проверить в течение 24 ч |
| Изменение `path.alias` у опубликованной сущности без записи 301 | ≥1 → немедленно |
| Снятие с публикации товара, у которого есть клики за 12 мес | ≥1 → немедленно |
| Клики T1 URL (7 дней) против того же окна прошлого года | −25% при стабильных показах → проверить сниппет; −25% показов → проверить индексацию |
| Средняя позиция T1 URL по главному запросу | ухудшение > 2 позиций за 14 дней |
| Ошибки Product / Merchant listings в GSC | рост > 0 после релиза |
| Ручные меры (Manual actions) | любое сообщение → P0 |
| Множество URL в sitemap | изменение > 5% без запланированной причины |
| Hreflang-взаимность (краулинг) | < 100% |
| Lab LCP / CLS на эталонных типах | ухудшение механизма (LCP-элемент стал ленивым, CLS > 0.1 на новом типе) |

Реализация — простой ночной скрипт (GET ≤1 rps по эталонным URL и JSON:API-снимок) плюс еженедельный GSC-экспорт. Оповещение в Telegram/почту.

**Сайт:** haiershop.uz (Drupal 10.1+, Drupal Commerce 2, языки UZ (основной) и RU) · **Дата:** 19.11.2026

**Основание.** Аудит 01–12 в этой папке. Номера задач HS-xx совпадают с `10_AUDIT_EVIDENCE.csv`.

**Данные владельца (19.11.2026):**

## Часть B. Задачи в шаблонах и настройках (через API их не сделать)

### B1. Убрать фиктивный рейтинг из разметки товаров — HS-01 · P0
- **Сейчас:** на всех 310 товарных страницах в JSON-LD Product есть `"aggregateRating": {"ratingValue": "4.9", "reviewCount": 9}`, а на странице показано «Напишите первый отзыв». Это нарушение правил Google: отзывы в разметке должны быть видны на странице. Риск — ручная мера и потеря товарных сниппетов.
- **Где искать:** место, где формируется JSON-LD Product — Twig-шаблон темы `maintheme`, кастомный модуль или настройки Schema.org Metatag (значения одинаковые для всех товаров, значит, они в шаблоне или в настройках по умолчанию, а не в самих товарах).
- **Сделать:** удалить `aggregateRating` целиком. Выводить его снова — только из реальных отзывов (`commerce_product_review`) и только когда отзывы видны на странице.
- **Приёмка:** в HTML 5 случайных карточек нет `aggregateRating`; Rich Results Test — Product валиден, Review snippet отсутствует.
- **Откат:** вернуть шаблон из git.

### B2. Разметка возврата и доставки = реальные условия — HS-04 · P0
- **Сейчас:** `merchantReturnDays: 10`, доставка `0 UZS` по всему Узбекистану за 1–2 дня.
- **Возврат** (на всех товарах; Google также рекомендует общую политику на уровне Organization, а на уровне товара — только переопределения):
```json
"hasMerchantReturnPolicy": {
  "@type": "MerchantReturnPolicy",
  "applicableCountry": "UZ",
  "returnPolicyCategory": "https://schema.org/MerchantReturnFiniteReturnWindow",
  "merchantReturnDays": 14,
  "returnFees": "https://schema.org/FreeReturn",
  "refundType": "https://schema.org/FullRefund",
  "returnMethod": "https://schema.org/ReturnByMail"
}
```
  `returnMethod` уточнить у владельца: возврат курьером или в магазин (тогда `ReturnInStore`).
- **Доставка.** Бесплатно только по Ташкенту, регионы платные — одно значение на всю страну это не описывает. Варианты:
  - (а) если для Узбекистана Google поддерживает регион в `shippingDestination` (проверить по [документации Google](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing)) — два блока: Ташкент `0 UZS`, срок до 1 дня; остальные регионы — реальный тариф, срок до 3 дней;
  - (б) если не поддерживает или фиксированного тарифа для регионов нет — **убрать `shippingDetails`** (поле необязательное), чтобы не обещать бесплатную доставку в регионы.
- **Приёмка:** Rich Results Test без ошибок; значения совпадают с правилами на сайте.

### B3. Наличие в разметке и на странице вместо снятия с продажи — P0 (до отказа от снятия)
- **Сейчас:** `availability: InStock` жёстко на всех 310 товарах. Это было верно, пока отсутствующие товары снимались с публикации. Но снятие даёт 403 и выпадение из Google: так потеряны, например, AS18IDHHRA (RU), ES80V-F3 и HW105-BP14406S.
- **Сделать:**
  1. Наличие из склада (на сайте есть Commerce Stock) или из отдельного поля «В наличии / Нет в наличии / Под заказ».
  2. На странице — видимый статус «Нет в наличии» и блок похожих товаров. Страница остаётся опубликованной (200) и в sitemap.
  3. В JSON-LD — `OutOfStock` (или `PreOrder`) по тому же источнику.
  4. **Только после этого** менеджеры перестают снимать товары с публикации.
- **Приёмка:** тестовый товар с нулевым остатком → 200, видно «Нет в наличии», в JSON-LD `OutOfStock`, URL в sitemap.

### B4. 301-редиректы для потерянных адресов — HS-02 · P0
- **Сделать:**
  1. Установить модуль **Redirect**. В его настройках включить автоматическое создание редиректа при смене алиаса. После этого в Pathauto можно выбрать вариант «создать новый алиас и редирект со старого» (формулировки зависят от версии).

  3. Добавить 301 по `13a_REDIRECT_MAP.csv`:

  4. Партиями по 10, начиная с наибольших кликов.
- **Приёмка:** `curl -I <old_url>` → `301` → `Location: <new_url>` → `200`; цепочек нет.
- **Откат:** удалить запись редиректа.

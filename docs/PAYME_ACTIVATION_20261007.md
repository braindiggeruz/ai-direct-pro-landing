# Payme: запуск для чата и Studio, 07.10.2026

## Основание

Владелец сообщил об активации кассы Payme и прямо подтвердил включение Payme рядом с Click для чата и двух тарифов Studio: «ну давай всё подключай да! грамотно всё имплементируй…». Это отменяет его прежнее временное указание оставить только Click. Ранее интегратор сообщил об успешной сдаче песочницы; новая активация передана screenshot сообщением владельца. Скрин активации сам по себе не доказывает реальную оплату или фискальный чек.

## Реализация

Переиспользуется Merchant API `/api/payments/payme`, общая касса и три существующих продукта. `GPT_BILLING_MODE_PAYME=live` в packed JSON и обычной таблице; `STUDIO_PAYMENT_PROVIDERS=click,payme` в Studio JSON. Click live и его shared resolver сохранены, Uzum off, тарифы и оферта v5 не меняются. Чат20 000 сум (2 000 000 тийин); Studio Kunlik5 900 (590 000), Oylik39 900 (3 990 000).

Обработчик проверяет Basic auth до D1, точную сумму и режим заказа, различает `pay_*` и `stu_*`, исключает принадлежность одной Payme-транзакции двум продуктам. Повторные Create/Perform/Cancel не дублируют права; отмена отзывает только соответствующее право. Settlement начатых оплат работает при остановленных продажах. Payme формирует чек по `detail.items`; callback SetFiscalData сохраняет ссылку, собственная очередь не пробивает Payme-заказ второй раз.

Первые4 failures были старыми pin-тестами запрета Payme; они заменены строгой проверкой нового решения владельца, остальные негативные защиты сохранены.

## Откат

Вернуть только `GPT_BILLING_MODE_PAYME=test` в обоих местах и штатно выпустить. Для Studio Payme автоматически перестаёт предлагаться из-за несовпадения режима; Click остаётся. Payme не удалять из внутреннего GPT_PAYMENT_PROVIDERS и endpoint не выключать: боевые settlement/отмены должны доводиться production key. Не удалять купленные права, заказы и секреты.

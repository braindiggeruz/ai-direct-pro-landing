# Оплата через Uzum Bank: как включить и обслуживать

*Пакет C, 2026-09-30. Источники: портал разработчика https://developer.uzumbank.uz/en/ и три публичные спецификации, скачанные 2026-09-30 в `docs/paid-chat/uzum-spec/`: Uzum Checkout 1.10.3 (`en_checkout.yaml`), Merchant API 1.0.0 (`en_merchant.yaml`), Fiscalization 0.0.2 (`en_fiscalization.yaml`).*

## 1. Коротко

- Код готов и выключен. Пока не заданы `UZUM_API` и секрет `UZUM_CREDENTIALS_JSON` (а для Checkout в боевом режиме ещё и `UZUM_CHECKOUT_BASE_URL`), адреса Uzum отвечают 404, база не читается, кнопки Uzum в чате нет.
- Поддержаны оба продукта Uzum:
  - **Uzum Checkout** (`UZUM_API="checkout"`). Это страница оплаты картой для сайта: принимает Humo и Uzcard любого банка. Кнопка «Uzum Bank» появляется в чате рядом с Click и Payme.
  - **Merchant API** (`UZUM_API="merchant"`). Человек платит внутри приложения Uzum Bank и вводит там код заказа. Серверная часть готова, экрана с кодом заказа на сайте пока нет. Делаем его, когда станет ясно, какой договор у вас.
- Одновременно работает только один из двух режимов.
- **Рекомендация для конверсии: Checkout.** Посетитель остаётся в привычном сценарии «нажал — ввёл карту — вернулся в чат», и платить можно картой любого банка. В Merchant API человеку нужно открыть приложение Uzum, найти услугу и ввести код. Каждый такой шаг теряет часть покупателей, а платить могут только клиенты Uzum Bank.
- Цена, пакет и доступ те же, что у Click и Payme: 20 000 сум, 300 ответов на календарный месяц. Uzum записывается в тот же журнал, открывает тот же доступ и шлёт вам те же уведомления в Telegram.

## 2. Что спросить у менеджера Uzum

1. Какой продукт в договоре: Checkout (оплата картой на сайте), Merchant API (оплата в приложении Uzum Bank) или оба.
2. **Адреса API для теста и для боя.** В публичной спецификации их нет. Тестовый адрес по умолчанию `https://test-chk-api.uzumcheckout.uz` взят из стороннего SDK и **не проверен**. Боевого адреса по умолчанию нет вообще, без него боевой Checkout не включится.
3. Для Checkout: `X-Terminal-Id` (UUID терминала) и `X-API-Key`, отдельно для теста и для боя.
4. Для Merchant API: `serviceId`, логин и пароль Basic-авторизации, отдельно для теста и для боя.
5. Адреса уведомлений, которые нужно прописать на терминале:
   - Checkout (оплаты, возвраты и чеки): `https://gptbot.uz/api/payments/uzum`
   - Merchant API: `https://gptbot.uz/api/payments/uzum-merchant/check`, `…/create`, `…/confirm`, `…/reverse`, `…/status`. Уточните, дописывает ли Uzum `/check`, `/create` и остальные к одному базовому адресу. Если да, базовый адрес `https://gptbot.uz/api/payments/uzum-merchant`.
6. **Подписаны ли уведомления Checkout и приходят ли они с фиксированных IP.** В спецификации подписи нет. Поэтому наш сервер никогда не верит уведомлению на слово: перед любым изменением оплаты он сам запрашивает статус заказа у Uzum своими ключами. Если Uzum даст подпись или список IP, их можно добавить как дополнительную защиту.
7. Нужна ли автофискализация. По умолчанию она выключена, включает её менеджер Uzum. Если её не включить, кто выдаёт чек?
8. Комиссия, сроки зачисления, минимальная сумма, частичные возвраты. У нас в этом этапе только полные возвраты.
9. Можно ли в приложении Uzum ввести код заказа вида `uzm_…` (32 шестнадцатеричных символа). В примерах документации код заказа числовой. Вопрос только для Merchant API.
10. Разрешено ли название услуги «AI paket 300 · gptbot.uz». Слов «GPT» и «ChatGPT» в платёжных данных нет.

## 3. Данные чека (общие для Click и Uzum)

Решение владельца от 01.10.2026, значения уже в `wrangler.toml`:

- `GPT_FISCAL_IKPU = "10305008002000000"` — ИКПУ (SPIC) услуги, 17 цифр, по каталогу https://tasnif.soliq.uz/ (действует, маркировка не нужна).
- `GPT_FISCAL_PACKAGE_CODE = "1514296"` — код упаковки «услуга (раз)».
- `GPT_FISCAL_VAT_PERCENT = "12"` — ставка НДС. НДС **входит** в цену: в 20 000 сум 2 142,86 сум НДС.
- `GPT_FISCAL_TIN` — ИНН продавца (его передаёт только чек Click).

Uzum берёт их, когда включена автофискализация (`UZUM_AUTOFISCAL = "true"`). Если хотя бы одно значение не заполнено или неверно, новые оплаты Uzum не принимаются. Чек без обязательных данных мы не создаём. Боевая продажа через Checkout без автофискализации не открывается вовсе (`liveReadiness()` называет `UZUM_AUTOFISCAL`). Merchant API в бою требует ключ Uzum Fiscalization API в секрете (`fiscal.live.apiKey`).

## 4. Как включить

### 4.1. Секрет `UZUM_CREDENTIALS_JSON`

Один секрет вместо шести: на бесплатном тарифе Workers число переменных ограничено. Задаётся в Cloudflare Pages → Settings → Environment variables, тип **Secret**. В файлы проекта, чаты и логи его не вставляйте.

```json
{
  "checkout": {
    "test": { "terminalId": "<UUID тестового терминала>", "apiKey": "<тестовый X-API-Key>" },
    "live": { "terminalId": "<UUID боевого терминала>", "apiKey": "<боевой X-API-Key>" }
  },
  "merchant": {
    "test": { "serviceId": 0, "login": "<логин>", "password": "<пароль>" },
    "live": { "serviceId": 0, "login": "<логин>", "password": "<пароль>" }
  },
  "fiscal": {
    "test": { "apiKey": "<тестовый ключ Fiscalization API>" },
    "live": { "apiKey": "<боевой ключ Fiscalization API>" }
  }
}
```

Разделы, которых нет в договоре, можно не заполнять. `serviceId` — число из договора, `0` в примере только место для него. Логин не может содержать двоеточие. Если JSON неверный, Uzum просто остаётся выключенным: сервер не угадывает и не подставляет значения.

### 4.2. Публичные настройки

Каждое значение пишем **в двух местах `wrangler.toml`**: в блоке `[vars.GPTBOT_RUNTIME_CONFIG]` и в упакованной строке `GPTBOT_RUNTIME_CONFIG_JSON`. Тест `tests/runtime-config.test.ts` не даст им разойтись. После правки нужен деплой.

| Ключ | Значение |
|---|---|
| `UZUM_API` | `""` — выключено; `"checkout"` или `"merchant"` |
| `UZUM_CHECKOUT_BASE_URL` | боевой адрес API от Uzum; только https и только домены uzumbank.uz, uzumcheckout.uz или uzum.uz |
| `UZUM_CHECKOUT_TEST_BASE_URL` | тестовый адрес; по умолчанию `https://test-chk-api.uzumcheckout.uz` (не проверен) |
| `GPT_BILLING_MODE_UZUM` | `""` — как `GPT_BILLING_MODE`; `"test"`, `"live"` или `"off"` только для Uzum |
| `GPT_PAYMENT_PROVIDERS` | разрешённые провайдеры, по умолчанию `"click,uzum"` |
| `UZUM_AUTOFISCAL` и `GPT_FISCAL_*` | см. раздел 3 |

Если Uzum выдаст адрес на другом домене, нужно поправить одну строку `UZUM_HOST_PATTERN` в `functions/lib/gpt-chat/uzum-config.ts` и `UZUM_CHECKOUT_HOST` в `src/gpt-chat/types.ts` (тест проверяет, что они совпадают). Этот список защищает ключ API: из-за опечатки в настройке ключ не уйдёт на чужой сервер.

### 4.3. Порядок запуска

1. **Миграция.** До деплоя кода примените `migrations/0065_gpt_uzum_payments.sql` к базе `gptbot-ai-drafts` так же, как применяли 0064 (`docs/readiness/2026-09-06/`), например `npx wrangler d1 migrations apply gptbot-ai-drafts --remote`. Она создаёт таблицу `gpt_uzum_orders` и представление `gpt_payment_orders_all`. Перед этим сделайте резервную копию D1. Если D1 не примет `CREATE VIEW`, не деплойте код: без представления не откроется раздел «Мой тариф».
2. **Тест без денег.** `GPT_BILLING_MODE_UZUM="test"`, `UZUM_API="checkout"`, в секрете раздел `checkout.test`. Тестовый режим тёмный: посетители его не видят. Uzum в тесте предлагается только в сессии репетиции, то есть браузеру с cookie `__Host-gpt_rehearsal`. Её выдаёт `POST /api/internal/gpt-rehearsal-session` с Bearer `GPT_BILLING_MAINTENANCE_SECRET`. Прогоните `node --import tsx scripts/uzum-sandbox-rehearsal.ts` с тестовыми ключами в окружении: он создаёт заказ, выдаёт ссылку на страницу оплаты, следит за статусом, а с `--refund` ещё и возвращает деньги. Тестовые карты указаны в спецификации (раздел Testing): HUMO 9860 0901 0121 9724 (до 10/26) и Uzcard 8600 3129 2957 7175 (до 09/26), код 3-DS 777777. **Эти карты истекают в сентябре и октябре 2026 года, запросите у Uzum актуальные.** В тестовом режиме сайт, как и для Click и Payme, не выдаёт ссылку на оплату: проверяется протокол, а не деньги.
3. **Бой со скрытым запуском.** `GPT_BILLING_MODE_UZUM="live"`, `GPT_BILLING_LIVE_READY="true"` и всё, что называет `liveReadiness()` в `functions/lib/gpt-chat/billing-config.ts`: опубликованные оферта RU/UZ, `GPT_BILLING_TERMS_VERSION`, `GPT_BILLING_TERMS_APPROVED_AT` (дата одобрения юристом), `UZUM_CHECKOUT_BASE_URL`, раздел `checkout.live`, автофискализация, канал уведомлений, соль, `GPT_IDENTITY_SECRET`, `GPT_BILLING_MAINTENANCE_SECRET` и способ входа. Купите пакет сами, проверьте, что доступ открылся, в Telegram пришло «GPTBot.uz · AI paket: paid / uzum», а в разделе «Мой тариф» появилась ссылка на чек (при автофискализации). Затем сделайте учебный возврат (раздел 6).
4. Откройте оплату всем.

## 5. Как это работает (для проверки)

- **Checkout.** Посетитель вошёл через Telegram, принял оферту и нажал «Uzum Bank». Сервер регистрирует заказ в Uzum: сумма 2 000 000 тийинов, номер заказа `uzm_…`, возврат на `/uz/gpt-uzbek-tilida/` или `/ru/gpt-chat/`. Затем отправляет человека на страницу оплаты Uzum. Сессия оплаты длится 30 минут. Повторное нажатие в течение этого времени открывает ту же страницу, второй заказ не создаётся.
- **Уведомление от Uzum** (`/api/payments/uzum`) служит только подсказкой. Сервер находит заказ по двум номерам, наш `uzm_…` и `orderId` Uzum, и сам запрашивает `getOrderStatus`. Доступ открывается, только если Uzum ответил `COMPLETED`, а сумма и номер заказа совпали. Если заказ неизвестен или чужой, сервер отвечает 200 и ничего никуда не запрашивает. Если Uzum не ответил на запрос статуса, сервер отвечает 502, и Uzum присылает уведомление ещё раз (до 5 раз).
- **Потерянное уведомление.** Когда посетитель вернулся на сайт или нажал «Проверить статус», сервер сам спрашивает у Uzum статус ожидающего заказа, не чаще 6 раз в час на аккаунт.
- **Сомнительные случаи в доступ не превращаются.** Вам приходит уведомление в Telegram с кодом сбоя:
  - `uzum_amount_mismatch` — сумма или номер заказа не совпали;
  - `uzum_partial_refund` — частичный возврат;
  - `uzum_paid_after_cancel` — деньги списаны по заказу, который мы уже закрыли. Разберитесь вручную: верните деньги или выдайте доступ;
  - `uzum_status_conflict` — после оплаты пришёл отказ;
  - `uzum_processing` — ошибка сервера.
- **Повторы безопасны.** Одно и то же уведомление, пришедшее много раз, даёт один доступ, одну запись в журнале и одно сообщение вам. Это проверяет тест.
- **Merchant API** (`/api/payments/uzum-merchant/<op>`). Логин и пароль проверяются за постоянное время до любого обращения к базе. Сервер отвечает кодами Uzum (10001–10018, 99999). Если транзакцию не подтвердили за 30 минут, она закрывается, и в `/status` приходит `FAILED`. Номер телефона из `/confirm` не записывается и не попадает в логи.

## 6. Возврат денег

Только полный и только для оплат Checkout. Пока Uzum не подтвердит возврат, доступ остаётся открытым: иначе человек потерял бы и доступ, и деньги.

**Вариант А: вернуть через наш сервер** (Uzum `POST /api/v1/acquiring/refund`):

```bash
curl -X POST https://gptbot.uz/api/internal/gpt-uzum-refund \
  -H "Authorization: Bearer <GPT_BILLING_MAINTENANCE_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{"orderId":"uzm_…","confirmRefund":true}'
```

- Номер операции (`X-Operation-Id`) создаётся один раз и сохраняется до запроса в Uzum. Если связь оборвалась, повторите ту же команду: деньги не вернутся дважды.
- Ответ `requested: true` значит, что Uzum принял запрос. Заказ станет «возвращён», а доступ закроется, когда Uzum сообщит `REFUNDED`: уведомлением, сразу после запроса или при «Проверить статус».
- При автофискализации к возврату автоматически прикладывается корзина с ИКПУ. Без неё Uzum вернёт ошибку 3045.

**Вариант Б: вернули в кабинете Uzum, отметить у нас:**

```bash
curl -X POST https://gptbot.uz/api/internal/gpt-uzum-refund \
  -H "Authorization: Bearer <GPT_BILLING_MAINTENANCE_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{"orderId":"uzm_…","merchantRefundReference":"<номер возврата из кабинета>","confirmedRefund":true}'
```

Сервер сначала спрашивает Uzum. Отметка ставится, только если Uzum сообщает, что вся сумма возвращена. Иначе ответ 409, и ничего не меняется.

Заказ из Merchant API возвращает сам Uzum своим запросом `/reverse`. Отдельная команда для него не нужна.

## 7. Выключение и откат

- **Остановить новые оплаты, не теряя подтверждений:** `GPT_BILLING_LIVE_READY="false"`. Это останавливает новые оплаты у всех провайдеров, а уведомления Uzum продолжают приниматься.
- **Выключить Uzum полностью:** `GPT_BILLING_MODE_UZUM="off"`, `UZUM_API=""` или удалить секрет. После этого адреса Uzum отвечают 404. Делайте это, только когда ожидающие заказы Uzum закрылись: сессия Checkout длится 30 минут, транзакция Merchant API тоже 30 минут, счёт живёт 12 часов.
- **Переключаться между Checkout и Merchant API** тоже стоит, когда открытых заказов Uzum нет. Открытый заказ одного режима не используется для другого.
- Таблицу `gpt_uzum_orders` **не удалять**: это финансовые записи. Представление `gpt_payment_orders_all` можно удалить только вместе с откатом кода к версии до 0065.

## 8. Проверка в базе

```sql
-- заказы Uzum за сутки по состояниям
SELECT api, mode, state, COUNT(*) FROM gpt_uzum_orders
WHERE org_id='gptbot-consumer' AND created_at > (strftime('%s','now')-86400)*1000 GROUP BY 1,2,3;
-- неотправленные уведомления владельцу (Click, Payme и Uzum вместе)
SELECT p.provider, o.event, COUNT(*) FROM gpt_billing_outbox o
JOIN gpt_payment_orders_all p ON p.org_id=o.org_id AND p.id=o.order_id
WHERE o.delivered_at IS NULL GROUP BY 1,2;
-- сбои Uzum
SELECT code, created_at FROM gpt_service_alerts WHERE code LIKE 'uzum_%' ORDER BY created_at DESC LIMIT 20;
```

## 9. Что не проверено

- Адреса API Uzum (тестовый взят из стороннего SDK, боевого нет) и то, что наш список доменов их покрывает.
- Подпись уведомлений и IP-адреса Uzum: в публичной спецификации их нет.
- Формат ответа при повторном возврате с тем же `X-Operation-Id`. Код 3028 «операция уже существует» считаем принятым повтором.
- Присылает ли Uzum уведомление `DECLINED`, когда время сессии вышло. Если нет, такой заказ закрывается при следующей проверке статуса, через 35 минут после создания.
- Как Merchant API вызывает наши адреса и принимает ли приложение код заказа `uzm_…`.
- Экран Merchant API на сайте (код для приложения Uzum) не сделан намеренно, до ответа на вопрос 1 из раздела 2.

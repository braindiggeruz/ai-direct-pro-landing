# Оплата через Payme: песочница, переход в live, обслуживание

*Ветка `paid/payme-20261006`, 2026-10-06. Требования и разбор пробелов: `gptbot.uz-audit/raw/payme-2026-10-06/PAYME-REQUIREMENTS.md` (вне репозитория). Источники: https://developer.help.paycom.uz (Merchant API, инициализация платежа, песочница). Код: `functions/api/payments/payme.ts` (Merchant API), `functions/lib/gpt-chat/payme-checkout.ts` (страница оплаты и чек), `functions/lib/gpt-chat/billing-config.ts` (режим и ключи), `functions/api/gpt/subscribe.ts` (кнопка Payme), `migrations/0074_gpt_payme_fiscal.sql`. Тесты: `tests/gpt-payme.test.ts`, `tests/gpt-live-readiness.test.ts`, `tests/legal-oferta.test.ts`.*

## 1. Коротко

- Касса Payme «с биллингом» (Merchant API). Адрес для Payme: `https://gptbot.uz/api/payments/payme`. Поле счёта: `order_id` (наш номер заказа `pay_` + 32 символа, всего 36 символов, текстовое поле).
- Сейчас Payme в **тестовом режиме** (`GPT_BILLING_MODE_PAYME = "test"`). Обычные посетители видят только Click. Кнопку Payme видит только браузер с сессией репетиции (админка → «AI-чат» → «Открыть сессию репетиции»). Оплата идёт на песочницу `https://test.paycom.uz`, деньги не списываются.
- Адрес `/api/payments/payme` в тестовом режиме принимает только тестовый ключ кассы. Боевой ключ в тестовом режиме не подходит, и наоборот.
- Чек печатает сам Payme. В ответе на CheckPerformTransaction мы отдаём строку чека: «AI paket 300 (xizmat, 1 oy)», 20 000 сум, ИКПУ 10305008002000000, код упаковки 1514296, НДС 12 % включён. Наша очередь чеков заказы Payme не трогает: двух чеков на одну оплату не будет.
- Live включается только отдельным решением после одобрения Payme (раздел 6).

## 2. Настройки

Публичные (в `wrangler.toml`, в двух местах: упакованный JSON и таблица):

| Настройка | Сейчас | Что значит |
|---|---|---|
| `GPT_PAYMENT_PROVIDERS` | `"click,uzum,payme"` | Payme разрешён вообще. Без `payme` адрес Payme отвечает 404. |
| `GPT_BILLING_MODE_PAYME` | `"test"` | Режим Payme: `"test"`, `"live"` или пусто/`"off"`. Пусто значит «как `GPT_BILLING_MODE`» (там пусто). Click и Uzum эта настройка не затрагивает. |

Секреты Cloudflare Pages (значений в репозитории и в логах нет): `GPT_PAYME_MERCHANT_ID` (ID кассы, 24 символа, один для теста и боя), `GPT_PAYME_TEST_KEY` (тестовый ключ), `GPT_PAYME_KEY` (боевой ключ). Если ключ случайно положили с переводом строки, код его обрезает. Ключ неверного вида — то же, что его нет: адрес отвечает 404, кнопки нет.

## 3. Что нужно до песочницы (владелец и агент)

1. **Выкатить эту ветку** (песочница Payme звонит на боевой адрес сайта). Перед выкатом применить миграцию `0074_gpt_payme_fiscal.sql` (`wrangler d1 migrations apply --remote`; она только создаёт таблицу, порядок с кодом не важен). Проверка после выката: `inert-smoke.mjs … --click-live --payme-test --bearer-file …`.
2. **Cloudflare:** минимальная версия TLS для зоны gptbot.uz — не выше 1.2 (Payme ходит по TLS 1.0–1.2). На `/api/payments/payme` не должно быть проверки бота или челленджа: после первого запроса Payme посмотреть Security Events.
3. **Кабинет Payme (business.paycom.uz):** у кассы адрес `https://gptbot.uz/api/payments/payme`, поле `order_id` — текст до 36 символов (числовая маска даст ошибку `-31610` на странице Payme).
4. **Наша проверка перед песочницей** (агент, 1 минута):
   ```
   node gptbot.uz-audit/raw/payme-2026-10-06/payme-smoke.mjs https://gptbot.uz \
     --key-file <файл с GPT_PAYME_TEST_KEY> \
     --bearer-file C:/Users/Borinio/.config/gptbot-private/gpt-billing-maintenance-secret.txt
   ```
   Скрипт сам открывает сессию репетиции с тестовым аккаунтом, создаёт два тестовых заказа и прогоняет те же вызовы, что песочница: неверная авторизация, неверная сумма, несуществующий счёт, создание и повтор, вторая транзакция (-31008), отмена до и после проведения, CheckTransaction, GetStatement. Ключ читается из файла и не печатается. Ожидаемо: `38/38 pass`.

## 4. Песочница test.paycom.uz (владелец)

1. Открыть https://test.paycom.uz, ввести **Merchant ID** кассы и **тестовый ключ** (TEST_KEY из кабинета). Тип счёта: **«Одноразовый»**.
2. Каждому сценарию нужен свой свежий заказ:
   - админка `/admin-tools/ai-chat` → «Открыть сессию репетиции» (галочка «Войти тестовым аккаунтом») → в этом же браузере открыть чат → окно «AI paket» → отметить оферту → **«Оплатить через Payme»**;
   - браузер уйдёт на `https://test.paycom.uz/…`; номер заказа `pay_…` виден в списке платежей админки (режим «тест»). Этот номер вводится в песочнице как `order_id`, сумма 2 000 000 тийинов (20 000 сум).
3. Сценарий 1 (создание и отмена непроведённой транзакции) — сначала: в нём проверки безопасности. Сценарий 2 (создание, проведение, отмена проведённой) — на новом заказе.
4. Ожидаемые ответы: неверная авторизация — `-32504`; неверная сумма — `-31001`; несуществующий счёт — `-31050` (`data: "order_id"`); новая транзакция для счёта «В ожидании оплаты» — `-31008`; повторы Create/Perform/Cancel — тот же ответ, что в первый раз; отмена проведённой — состояние `-2`.
5. После прохождения: отправить результат Payme (Жонибек) и попросить одобрить подключение к боевой среде.

## 5. Как это работает

- Кнопка Payme → `/api/gpt/subscribe` создаёт заказ и отдаёт адрес оплаты `https://test.paycom.uz/<base64>` (в live — `https://checkout.paycom.uz/<base64>`) с параметрами `m` (касса), `ac.order_id`, `a=2000000`, `c` (возврат в чат с `?pay=return`), `l` (ru/uz), `ct=15000` (через 15 с после оплаты Payme возвращает человека). Платят только с входом через Telegram (гостевая оплата — только Click).
- Если Payme уже держит транзакцию по заказу, повторное нажатие не открывает новую страницу (Payme ответил бы `-31008`), окно показывает статус оплаты.
- Payme вызывает: CheckPerformTransaction → CreateTransaction → PerformTransaction (пакет открывается) или CancelTransaction. Транзакция, не проведённая за 12 часов от времени её создания в Payme, отменяется с причиной 4.
- Один заказ — одна транзакция Payme. Повторы Payme получают тот же ответ.
- SetFiscalData (Payme сообщает о напечатанном чеке): чек сохраняется в `gpt_payme_fiscal` (номер чека, терминал, фискальный признак, ссылка, дата), ссылка на ofd.soliq.uz появляется в «Мой пакет». Ссылку не https мы не храним, но вызов принимаем, чтобы Payme его не повторял без конца.

## 6. Переход в live (после одобрения Payme)

Нужно всё сразу, одним выкатом:
1. Новая редакция оферты и обеих политик конфиденциальности, где Payme назван способом оплаты и получателем данных; новая `GPT_BILLING_TERMS_VERSION` и дата одобрения юристом. Сейчас тексты называют только Click и Uzum Bank, поэтому **гейт деплоя (`scripts/release/live-gate.ts`) не пропустит Payme в live**, пока Payme не назван в обеих офертах и обеих политиках.
2. `GPT_BILLING_MODE_PAYME = "live"` в обоих местах `wrangler.toml`. Глобальный `GPT_BILLING_MODE = "live"` Payme в live не переводит: нужен именно его переключатель.
3. Проверка: `npx tsx scripts/release/live-gate.ts --assume-live payme` — пустой список проблем; в админке «Готовность» у Payme пусто.
4. После первой боевой оплаты **сменить боевой ключ в кабинете Payme** и положить новый в секрет `GPT_PAYME_KEY` (ключи были присланы в чат).

## 7. Возвраты и стоп-краны

- Оплаченный пакет не возвращается (оферта, раздел 8); исключения — ошибочное списание или требование закона. Деньги возвращает владелец **в кабинете Payme** (merchant.paycom.uz). Payme сам присылает CancelTransaction: заказ становится «возвращён», пакет закрывается, вам приходит уведомление в Telegram («AI paket: refunded · payme»; только по боевым заказам). **Вручную возврат Payme в админке не записывать** (запись возврата в админке — только для Click и Uzum).
- Остановить новые продажи всех провайдеров: `GPT_BILLING_LIVE_READY = "false"` → выкат (начатые оплаты завершатся).
- Выключить Payme совсем: `GPT_BILLING_MODE_PAYME = ""` → выкат. Адрес отвечает 404, начатые транзакции Payme провести не сможет.
- Срочные алерты в Telegram (`ALERTS-RU.md`; приходят в течение 15 минут, не чаще раза в час на код): `payme_fiscal_failed` — Payme не пробил чек по боевой оплате (SetFiscalData с ошибкой; по тестовой алерта нет), смотреть `gpt_payme_fiscal` и кабинет Payme; `payme_processing` — ошибка сервера на запросе Payme (Payme повторит), либо не заданы фискальные коды `GPT_FISCAL_*` и каждая оплата отклоняется. В тестовом режиме `payme_processing` тоже приходит: репетиция должна видеть свои сбои.

## 8. Вопросы к Payme

1. Поле `order_id`: подтвердить текстовый тип и длину 36 символов (`pay_…`).
2. Включён ли для кассы SetFiscalData и совпадает ли `id` в нём с `id` транзакции из CreateTransaction (по нему мы находим заказ).
3. Включена ли для кассы фискализация по `detail` из CheckPerformTransaction.
4. Принимает ли страница оплаты параметр `c` со строкой запроса (`…/ru/gpt-chat/?pay=return`). Если нет — вернём адрес без `?pay=return`: окно и так найдёт оплату по памяти браузера.

## 9. Справка по кодам

`-32504` нет прав (неверная авторизация) · `-32300` не POST · `-32700` не JSON · `-32600` неверный запрос · `-32601` нет метода · `-32400` системная ошибка (в том числе нет фискальных настроек) · `-31001` неверная сумма · `-31050` заказ не найден или не оплачивается (`data: "order_id"`) · `-31008` операцию выполнить нельзя · `-31003` транзакция не найдена · SetFiscalData: `-32001` чек не найден, `-32602` неверный параметр (в `data` его имя). Все ответы — HTTP 200 с тем же `id`, что в запросе.

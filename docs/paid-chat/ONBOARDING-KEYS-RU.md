- Когда агент скажет, что локальные проверки закончены, удалите файлы с ключами (`click.json`, `uzum.json`, `zai.txt`). Копий нигде не оставляйте: ключи уже лежат в Cloudflare.

## 0. Куда класть файлы (владелец)

Папка: `F:/Claude/gptbot-keys-inbox/`. Каждый файл — простой текст в кодировке UTF-8.

**Как сохранить файл в Блокноте.** «Файл → Сохранить как», в поле «Тип файла» выбрать «Все файлы (\*.\*)», имя ввести целиком, например `click.json`. Иначе Windows тихо допишет `.txt`, и получится `click.json.txt`. Скрипт такой файл заметит и попросит переименовать.

**Правила для всех файлов:**
- значения пишутся в кавычках, как в примерах;
- если чего-то у вас нет, этот блок или поле просто не пишите. Не придумывайте значения и не оставляйте заглушки;
- лишние поля скрипт не пропустит: опечатку в названии поля он покажет как `unknown field`;
- файл всегда кладётся целиком, со всем, что у вас есть. Секрет на сайте заменяется полностью: если, например, в новом `click.json` только блок `test`, боевые ключи из секрета пропадут. Скрипт об этом предупредит.

| Файл | Что внутри | Секрет? |
|---|---|---|
| `click.json` | ключи Click: боевые (`live`) и, если Click их дал, тестовые (`test`) | да |
| `uzum.json` | какой договор Uzum (`api`), ключи и адреса Uzum | да |
| `zai.txt` | одна строка — ключ Z.ai | да |
| `business.json` | реквизиты продавца и данные чека | нет |

### `click.json`

```json
{
  "live": {
    "service_id": "<service_id из кабинета Click>",
    "merchant_id": "<merchant_id>",
    "secret_key": "<секретный ключ>",
    "merchant_user_id": "<id пользователя Merchant API>"
  },
  "test": {
    "service_id": "<тестовый service_id>",
    "secret_key": "<тестовый секретный ключ>"
  }
}
```

- `service_id`, `merchant_id` и `merchant_user_id` — только цифры.
- Блок `test` нужен, только если Click выдал отдельный тестовый сервис. Без него тест проходит на блоке тёмной репетиции, который сгенерировал агент.
- Тестовый блок нельзя собирать из боевых ключей.

### `uzum.json`

```json
{
  "api": "checkout",
  "checkout": {
    "live": { "terminalId": "<UUID боевого терминала>", "apiKey": "<боевой X-API-Key>" },
    "test": { "terminalId": "<UUID тестового терминала>", "apiKey": "<тестовый X-API-Key>" }
  },
  "merchant": {
    "live": { "serviceId": "<serviceId из договора>", "login": "<логин>", "password": "<пароль>" },
    "test": { "serviceId": "<тестовый serviceId>", "login": "<логин>", "password": "<пароль>" }
  },
  "fiscal": {
    "live": { "apiKey": "<боевой ключ Fiscalization API>" },
    "test": { "apiKey": "<тестовый ключ Fiscalization API>" }
  },
  "baseUrls": {
    "checkoutLive": "<боевой адрес API Checkout от Uzum>",
    "checkoutTest": "<тестовый адрес, если Uzum назвал другой>",
    "fiscalLive": "<адрес Fiscalization API, если отличается от спецификации>",
    "fiscalTest": "<тестовый адрес Fiscalization API, если отличается>"
  },
  "autofiscal": true,
  "serviceTitle": "AI paket 300",
  "accountField": "account"
}
```

- `api`: `"checkout"` — оплата картой на странице Uzum, `"merchant"` — оплата в приложении Uzum Bank по коду. Раздел с тем же названием должен быть в файле.
- Разделы, которых нет в договоре, не пишите. Для Checkout обычно нужны `checkout`, `baseUrls.checkoutLive` и либо `autofiscal: true` (Uzum сам печатает чек), либо `fiscal`.
- `autofiscal` — `true` только после того, как Uzum включил автофискализацию на терминале. Пишется без кавычек.
- `serviceTitle` и `accountField` сайт не читает. Скрипт только сверяет их: название без «GPT», «Plus», «Pro», «obuna» и «подписка»; поле кода — ровно `account`, потому что так его читает сайт.
- Адреса — только `https` и только на доменах Uzum (для Fiscalization API ещё `inplat-tech.com` и `ipt-merch.com`). Любой другой адрес скрипт отклонит: так ключ не уйдёт на чужой сервер.

### `zai.txt`

Одна строка — ключ Z.ai. Больше ничего: ни пробелов, ни подписи.

### `business.json`

Уже лежит в папке и принят. Он нужен снова, только если реквизиты изменятся.

```json
{
  "legalEntity": {
    "name": "<полное наименование, как в свидетельстве>",
    "shortName": "<краткое наименование>",
    "stir": "<СТИР, 9 цифр>",
    "legalAddress": "<юридический адрес>",
    "bank": "<банк>",
    "account": "<расчётный счёт, 20 цифр>",
    "mfo": "<МФО, 5 цифр>",
    "director": "<ФИО директора>",
    "email": "<e-mail>",
    "phone": "<телефон +998…>"
  },
  "fiscal": { "ikpu": "<ИКПУ, 17 цифр>", "packageCode": "<код упаковки>", "vatPercent": 12, "tin": "<ИНН = СТИР>" },
  "lawyerApprovedAt": "<ГГГГ-ММ-ДД>",
  "retentionDays": null

```

- **Новое наименование, адрес или директор** пишутся на двух языках: `{"ru": "…", "uz": "…"}`. Тогда меняются и русская, и узбекская страница оферты. Одна строка принимается, только если она говорит то же, что уже на сайте, без учёта регистра и кавычек.
- `email` и `phone` скрипт только сверяет с контактом сайта (`content/global/site.json`). Этот контакт стоит на каждой странице, поэтому его меняют отдельным релизом.
- `lawyerApprovedAt` и `retentionDays` скрипт проверяет и комментирует, но не записывает. Дата одобрения относится к конкретной редакции оферты и ставится по `OFFER-RU.md`. Срок хранения переписки меняет текст политики в том же релизе (`SALT-RU.md`).

   - Владелец открывает чек и сверяет: сумма 20 000, НДС 2 142,86, ИКПУ, количество 1, ИНН продавца.
   - Ответ запроса закрывает вопрос к Click о `payment_id`.
5. **Возврат этой покупки (проверка пути возврата)** — только когда чек уже пробит (шаг 4, `status_code = 0`). После возврата наш чек уже не уходит: очередь только один раз спросит Click, есть ли чек продажи, и ответа, пробивает ли Click чек сам, может не быть:
   1. владелец возвращает деньги в кабинете Click;
   2. в админке нажимает «Отметить возврат»: вводит номер заказа руками, затем номер возврата из кабинета, ставит галочку «деньги уже вернулись» и подтверждает (`ADMIN-RU.md`);
   3. проверяем: заказ в состоянии «возврат», пакет закрыт, владельцу пришло «AI paket: refunded».

   Чек возврата Click не описывает, этот вопрос решается с бухгалтером. Другой путь — `gpt-click-reversal` агентом (`CLICK-FISCAL-RU.md`). Им проверяется Merchant API, но для одной покупки выбирают один путь: второй возврат Click отклонит.
6. Семь дней наблюдаем: алерты, «Недели» в админке, чеки.

**Стоп-кран:** `GPT_BILLING_LIVE_READY = "false"` или `GPT_BILLING_MODE_CLICK = ""` → выкат. Колбэки по уже открытым заказам продолжают работать.

## S3. Uzum → тест

- **Checkout.**
  1. `UZUM_API = "checkout"` (его записывает `ingest-keys` из `uzum.json`) и `GPT_BILLING_MODE_UZUM = "test"` → коммит → выкат.
  2. Протокол уже проверен локально (шаг 2 приёма).
  3. Тестовая покупка тестовой картой на сайте в сессии репетиции. Проверяем: уведомление, сверку статуса, пакет и уведомление о чеке.
- **Merchant API.**
  1. `UZUM_API = "merchant"` и `GPT_BILLING_MODE_UZUM = "test"` → выкат.
  2. Uzum вызывает пять адресов своими тестами.
  3. С блоком репетиции агент проходит те же шаги сам: `dark-rehearsal.ts run --provider uzum …` (как в S1, п. 3).
  4. Экран с кодом оплаты смотрим в сессии репетиции.
- **Чеки в тесте.** Если в секрете есть `fiscal.test.apiKey`, тестовые чеки печатаются на `test-ofd.ipt-merch.com`. Ссылки на них Uzum просит прислать в их чат, прежде чем выдать боевой ключ.
- В конце режим снимается → выкат.

## S4. Uzum → живой режим

**Условия:** `liveReadiness(uzum)` пуст. Для Checkout — `UZUM_CHECKOUT_BASE_URL` и `UZUM_AUTOFISCAL = "true"` либо `fiscal.live.apiKey`. Для Merchant API — `fiscal.live.apiKey`. Гейт: `live-gate.ts --assume-live uzum` → `issues: []`.

1. `GPT_BILLING_MODE_UZUM = "live"`. Если Uzum включается раньше Click, то и `GPT_BILLING_LIVE_READY = "true"`. Тест «inert» переписывается так же, как в S2. Выкат.
2. **Владелец покупает пакет своей картой**, проверяет чек и пакет.
3. **Возврат этой покупки:**
   - Checkout: владелец возвращает деньги в кабинете Uzum, затем «Отметить возврат» в админке. Отметка пройдёт, только когда сам Uzum сообщит о полном возврате (`UZUM-RU.md`, раздел 7, вариант Б). Другой путь — `gpt-uzum-refund` агентом (вариант А).
   - Merchant API: Uzum возвращает деньги и присылает `/reverse`, пакет закрывается сам. Если Uzum вернул деньги без `/reverse`, нужна «Отметить возврат».
4. Семь дней наблюдаем. Стоп-кран тот же: `GPT_BILLING_LIVE_READY = "false"` или `GPT_BILLING_MODE_UZUM = ""` → выкат.

## S5. Z.ai: переключатель и оценка

**Сейчас.** Z.ai отвечает первым с 03.10.2026 по решению владельца:
- `GPT_MODEL_PROVIDER = "zai"`, `GPT_ZAI_EVAL_APPROVED = "2026-10-03"`, секрет `ZAI_API_KEY` в Pages;
- отчёт `docs/paid-chat/evals/zai-2026-10-03.json`.

Это быстрая проверка агента на 20 вопросах, а не слепая оценка носителями языка. Русский хороший, узбекский заметно слабее (`docs/paid-chat/eval/zai-check-2026-10-03-free.md`). Платные модели Z.ai ждут пополнения баланса.

**Оценка, которую нужно провести** (решение L10):
1. **Ключ.** Новый ключ (например, после смены) владелец кладёт в `zai.txt`, агент принимает его как в разделе 1 и выкатывает.
2. **Слепая проба:**
   ```powershell
   node --import tsx scripts/zai-blind-eval.ts --dry-run
   node --import tsx scripts/zai-blind-eval.ts
   node --import tsx scripts/zai-blind-eval.ts --paid
   ```
   - `--dry-run` — проверка без сети;
   - без флага — бесплатный уровень против бесплатной модели OpenRouter;
   - `--paid` — платный уровень после пополнения баланса.

   Ключи `ZAI_API_KEY` и `OPENROUTER_API_KEY` задаются только для этой команды. Скрипт их не печатает. Подробности — `ZAI-RU.md`, раздел «Слепая проба».
3. **Оценщики:** два носителя узбекского и один русского заполняют лист вслепую. Ключ «какая модель A, какая B» открывают после всех оценок.
4. **Порог:** узбекский не ниже 3,5 из 5 и не хуже текущей модели OpenRouter.
5. **Решение:**
   - **Прошёл.** Отчёт `docs/paid-chat/evals/zai-<дата>.json` (`decision: approved`, листы в репозитории), `GPT_ZAI_EVAL_APPROVED = "<дата>"` в двух местах → тесты `gpt-model-policy`, `gpt-zai-provider`, `runtime-config` → выкат.
   - **Не прошёл.** `GPT_MODEL_PROVIDER = "openrouter"` в двух местах → выкат. Другой вариант — `ZAI_TIERS = "paid"`: Z.ai только для платного уровня.
6. После пополнения баланса Z.ai: `ZAI_MODEL_PAID = "glm-4.5-air"` в двух местах → выкат.
7. 24 часа наблюдаем алерты `zai_*` и подпись модели под ответами.

**Откат:** `GPT_MODEL_PROVIDER = "openrouter"` → выкат. Срочно, без деплоя: блокировка `zai/*` в `gpt_model_health` (`ZAI-RU.md`, «Как выключить»).

**Юрист:** договор с Z.ai заключается в Сингапуре, Zhipu внесена в Entity List. Передачу данных за рубеж нужно обсудить с юристом (`ZAI-RU.md`, «Риски»).

## Откат (общий)

- **Продажи:** `GPT_BILLING_LIVE_READY = "false"` → выкат. Новые оплаты не принимаются, начатые завершаются.
- **Провайдер целиком:** снять его режим → выкат. Таблицы заказов не удалять.
- **Секрет:** удалить или заменить его через `ingest-keys` можно в любой момент, но действовать это начнёт только со следующим деплоем.
- Соль хешей после перекея не удалять. Worker при своём откате возвращает `AUTOSEND=true`, поэтому после отката Worker'а сразу деплой с `false` (план, §3, строка R1).

## Гарантии скрипта (проверяет тест)

`tests/paid-chat-ingest-keys.test.ts`:
- **Схемы.** Каждое пропущенное, неверное или неизвестное поле названо по имени и блокирует `--apply`. Секреты, которые скрипт собирается положить, читаются собственными парсерами сайта. Поле, которое отклоняет схема, отклоняет и сайт.
- **Вывод.** Значений из папки в выводе нет, даже в сообщении о сломанном JSON.
- **`--dry-run`** ничего не пишет и ничего не запускает.
- **`--apply`** отказывает при любой проблеме. Новый `wrangler.toml` собирается до первого `put`: значение, которое сайт принимает, а файл не может записать (например, кавычка в адресе), — это проблема уже в `--dry-run`. Если `put` упал, файлы репозитория не пишутся. Значение передаётся только через stdin, токен Cloudflare получает только wrangler, ошибка wrangler выводится с вырезанными значениями.
- **Тестовые блоки** тёмной репетиции сохраняются рядом с ключами владельца. Если у владельца свой тестовый блок, побеждает его блок. Пустая или неверная папка `--test-credentials` — ошибка. Если секрет уже есть в Pages, а в новом значении нет блока `test` или `live`, скрипт об этом предупреждает.
- **Папки** с ключами и с тестовыми блоками должны лежать вне репозитория.

Владелец 07.10.2026 одобрил реализацию roadmap и сначала запретил push/deploy до следующей команды. Затем прямо разрешил завершить production-проверки и выполнить deploy. Работа продолжена после зависания компьютера в `F:/Claude/gptbot-codex-integration-20261007`, ветка `codex/continuation-20261007`. Уже сохранённые изменения использованы; история Claude повторно не импортировалась.

## Реализованная поверхность

- На первом экране RU/UZ четвёртая плитка открывает презентацию внутри диалога. Остальные задачи чата сохранены; составление плана доступно через обычный запрос/шаблоны. В открытом диалоге есть отдельная кнопка презентации.
- Явный запрос создания на русском/узбекском открывает карточку с темой. Обычные вопросы о презентациях остаются текстовыми. Распознавание открывает форму, создание запускается только её кнопкой.
- Рекламные ссылки: `/ru/gpt-chat/?tool=presentation`, `/uz/gpt-uzbek-tilida/?tool=presentation`. Они открывают черновик без расходования единицы.
- Параметры, прогресс, слайды, картинки, заметки, скачивание PPTX, платная генерация и регенерация переиспользуют существующий Studio frontend/API. Отдельного backend, iframe или второго ledger нет.
- Карточки исключены из истории, отправляемой текстовой модели, и из числа текстовых ответов для коммерческих подсказок. Обычный чат сохраняет SSE.

## Хранение и восстановление

В истории чата хранится только typed reference `kind=presentation`, `artifactId` и исходная тема. Черновик, результат и Blob изображений хранятся отдельно в IndexedDB, с namespace владельца чата и идентификатором карточки. Старые текстовые истории совместимы; архивы сохраняют ссылку на карточку.

Хранилище принимает только проверенную ограниченную схему: 20 карточек, суммарно 32 MiB, 12 MiB на карточку, 2 MiB на картинку, срок 30 дней. Не сохраняются токены, подписанные URL, права или баланс. Сервер `/api/studio/me` остаётся источником прав. При смене владельца карточка перемонтируется; поздние операции старого компонента не обновляют новую карточку. Незавершённая генерация после reload помечается прерванной и автоматически не повторяется.

Если IndexedDB недоступна, результат остаётся в текущей вкладке с предупреждением. Переход к оплате требует успешного постоянного сохранения. При сбое сохранения checkout удерживает тот же заказ и повторяет переход без второго заказа. Перед очисткой браузера пользователь должен скачать файл; облачной синхронизации результатов здесь нет.

## Оплата и предложения тарифов

Backend допускает только два точных дополнительных return path: `/ru/gpt-chat/` и `/uz/gpt-uzbek-tilida/`. Возврат Studio помечен `?pay=return&product=studio`; кабинет текстового AI-пакета его не перехватывает. Локальная ссылка на нужную карточку сохраняется перед уходом; sessionStorage защищает возврат в той же вкладке от покупки в другой вкладке, localStorage служит запасным вариантом. Ссылка ограничена 24 часами и проверяется по владельцу. При возврате `/me` подтверждает состояние платежа, а карточка получает актуальный остаток через общий Studio runtime.

Контекстные предложения: после бесплатного результата; при выборе полной версии с нулевым остатком; после исчерпания бесплатной квоты. Скачивание бесплатного файла доступно сразу. Предложение после результата можно скрыть на сессию; кнопка полного пакета выделена градиентом. Цены и состав берутся из действующей конфигурации, заказы не создаются при показе.

Действующие продукты сохранены: AI-пакет чата 20 000 сум; Kunlik 5 900 сум / 1 полная презентация / 24 часа; Oylik 39 900 сум / 10 полных презентаций / календарный месяц. Полная презентация — максимум 12 содержательных слайдов, до 8 картинок, заметки и 3 палитры. Click и Payme используют прежние обработчики. Нового совместного SKU, обещания 15 слайдов или публичного фото-инструмента этот выпуск не вводит: R4/R5 в roadmap требуют отдельных экономики и качества.

## Сборка и ограничения

Studio загружается лениво в существующий React root; React/ReactDOM/scheduler deduplicated. Tailwind v4 Studio компилируется отдельно от Tailwind v3 сайта, без второго глобального reset. Скрипт `studio:deps` проверяет установленные точные версии и запускает `npm ci` только при недостающих/несовпадающих зависимостях перед root build/dev.

Начальные бюджеты сохранены: JS 110 000 B Brotli, собственный CSS 7 000 B, весь CSS страницы 27 000 B. Для именованных ленивых частей введены отдельные пределы: карточка 24 kB; тарифы 31 kB; кабинет 29 kB; возврат 30 kB; библиотека PPTX 120 kB. Ленивый CSS ограничен 8 kB. Исключения не увеличивают начальный бюджет или бюджет обычных модулей. PPTX скачивается только при экспорте. `VITE_CHAT_PRESENTATIONS=false` отключает новый host при сборке; standalone Studio остаётся рабочей.

## Риск прежней зависимости PPTX

`npm --prefix apps/studio audit --json` сообщает 2 high (одна уязвимая транзитивная библиотека `image-size@1.2.1` и её родитель `pptxgenjs@4.0.1`). Зависимости Studio не изменились относительно исходного коммита `0a9350cd`. Уязвимость — бесконечный цикл парсинга отдельных форматов изображений: [JXL/HEIF](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq), [ICNS](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr). В текущей браузерной библиотеке PPTX импортируется только JSZip, `image-size` отключён её browser map; в `functions/` нет импортов PPTX/image-size. Это ограничивает достижимость в действующей архитектуре, но не означает чистый dependency audit. При будущем Node/server-side экспорте нужна совместимая замена/обновление; `npm audit fix --force` не выполнялся.

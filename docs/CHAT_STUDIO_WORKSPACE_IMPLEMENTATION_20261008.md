## Архитектура

`usePresentationSession` извлечён из прежнего Form. Standalone Studio и main chat используют общий controller, flow/API, ledger и экспорт. Закрытие панели, смена mobile-вкладки и новый чат не уничтожают активный controller. Сохраняются 12 последних controller плюс выбранный и работающие задачи; старые документы доступны через существующее хранилище.

Локальные команды выполняет детерминированный закрытый parser. Они не отправляются текстовой модели, не увеличивают число AI-ответов и не покупают тариф. Неизвестная команда объясняет доступные действия; для общего вопроса есть «Обычный чат». Команда сокращения оставляет два пункта; это не интеллектуальное переписывание текста. Повтор без изменения не создаёт ложную новую версию. Исходный server task/job не изменяется, поэтому MAC и регенерация сохраняют свой контракт.

Preview использует общие размеры, layouts, fit и palettes с экспортом; SVG перенос слов приблизительный. Это не обещание пиксельной идентичности PowerPoint. Файл PPTX создаёт настоящий существующий exporter; заголовок и заметки проверены в ZIP/XML. Экспорт загружается только по действию скачивания.

## Покупки и новый триггер

Владелец сообщил: вчера 37 результатов `ChatEngaged`, оплат нет. Это данные владельца, а не проведённый нами аудит Ads Manager. Событие в коде означает первый успешный ответ за браузерную сессию и язык; оно не доказывает 37 уникальных покупателей. Причина нулевых продаж по этим двум числам не установлена.

Обнаруженный барьер: прежнее предложение появлялось после 10 ответов при бесплатном лимите 5/час. Теперь компактная карточка появляется после первого полезного ответа; при малом остатке объясняет лимит. Цена, количество ответов и срок берутся из действующего server account view. Прямые Click/Payme используют существующий checkout и актуальную редакцию оферты: нажатие принимает условия, отдельной страницы подтверждения нет.

Карточка не перекрывает работу, закрывается до следующего UTC-дня в этом браузере, не показывается при активном пакете/выключенной продаже/в режиме презентации. Бизнес-предложения и лимитная карточка не дублируются этим блоком. Ложных скидок, отзывов, дефицита и таймеров нет. Оплата и новая AI-генерация требуют действий пользователя.

Новые безопасные события: `pack_prompt_viewed`, `pack_prompt_clicked`, `pack_prompt_dismissed` в клиентской аналитике; серверные `pack_prompt_viewed`, `pack_prompt_dismissed` с закрытыми qualifiers `after_answer`/`near_limit`; `pack_viewed.after_value` → существующий `checkout_started` → `checkout_result`. View считается при >=50% видимости карточки. Тексты вопросов, темы документов и номера заказов в эти новые события не передаются. Повторы и ограничения D1 проверены. Новая миграция не нужна.

Достоверные продажи считать по серверным оплаченным заказам. Сопоставлять показы/открытия/начала/оплаты и рекламные расходы за одинаковые периоды после публикации; не выдавать новый UI за подтверждение окупаемости. Оптимизация кампании Meta и изменение её бюджета в этот этап не входят.

# Data Limitations — GSC-аудит gptbot.uz, 2026-09-17

## Доступ и property

- Данные получены через **OpenSEO MCP** (хостинг app.openseo.so), проект `7534113b-f748-4f98-ac39-9e3782d3d9e7`, который подключён к **одной** property `sc-domain:gptbot.uz`. Это существующая авторизованная интеграция аккаунта braindigger.uz@gmail.com; вызовы read-only (`get_search_console_performance`, `inspect_urls`), кредиты OpenSEO не тратятся.
- **Перечень всех properties (`sites.list`), Sitemaps API (`sitemaps.list`: last downloaded, errors, warnings), Index Coverage, Page Experience, Removals, Links — недоступны** через эту интеграцию. Сравнение доменной property с URL-prefix (`https://gptbot.uz/`, `https://www.gptbot.uz/`, http-варианты) выполнено косвенно: по фильтру `page` внутри доменной property (www — 2 показа, http — 2 показа) и по HTTP-редиректам.
- Локальные альтернативы проверены и не сработали: `gcloud auth print-access-token` — `invalid_grant` (просроченный refresh token); `~/.config/claude-seo/google-api.json` отсутствует; service-account/OAuth-файлов с `private_key`/`client_secret` на машине нет; секреты `GSC_CLIENT_ID/SECRET/REFRESH_TOKEN` существуют только в Cloudflare Pages (используются `functions/lib/gsc/sitemap.ts`) и не читаются локально; в `F:\Claude\seo-agent\.env` переменная `GSC_OAUTH` пустая.
- Для прямого доступа подготовлен минимальный скрипт `seo-audit/gsc-2026-09-17/scripts/gsc_direct_auth.py` (scope `webmasters.readonly`, локальный OAuth-flow). Запуск требует OAuth-клиента (client_secret JSON от Google Cloud) и подтверждения в браузере владельцем:
  ```bash
  python seo-audit/gsc-2026-09-17/scripts/gsc_direct_auth.py --client-secret <путь к client_secret.json> --list-sites
  ```
  Токен сохраняется в `~/.config/gptbot-gsc/token.json` (вне репозитория). Не выполнялся.

## История

- В property данные существуют только с **2026-05-21** (117 финальных дней до 2026-09-14). Запрос за 16 месяцев вернул API-границы 2025-05-17…2026-09-14, но строки — с 21 мая 2026. Год к году (yoy28 = 2025-08-19…2025-09-15) — 0 строк. «Предыдущие 90 дней» (2026-03-19…06-16) содержат 27 дней с данными (2 клика, 248 показов) — сравнение 90/90 формально есть, содержательно бесполезно.
- Известная проблема GSC (ненадёжные показы/CTR/позиция с 2025-05-13 по 2026-04-27, без бэкфилла) не затрагивает окно данных сайта.

## Полнота строк

- Пагинация `startRow` по 1 000 строк до `hasMore=false`; максимальный набор — 5 693 строки (`date × query`, 90 дней). Лимиты не достигнуты.
- **Анонимизированные запросы:** 35,3% кликов и 13,8% показов за 28 дней не раскрываются по запросу (72,5% кликов в предыдущие 28). Все кластерные доли считаны по раскрытой части; итоги property — по измерению `date`.
- Суммы по `page` (861 клик) и по `device`/`country` (843) за один период различаются — известное поведение GSC (страница vs property агрегация). В отчётах для итогов используется property-уровень (843).
- Измерение `date × query × page` не выгружалось; динамика доминирующего URL оценена по двум окнам (28 / предыдущие 28).

## Search appearance

- `searchAppearance` вернул 0 строк для всех периодов и типов. Неизвестно, отсутствуют ли данные или измерение не поддержано интеграцией. URL Inspection показывает только Breadcrumbs как rich result.

## URL Inspection

- Проверено 42 URL (батчами по 3 — при 10 URL интеграция таймаутила). Квота Google — 2 000/день; использовано ~2%. Не проверялись 247 URL sitemap; статус «indexed» для них выводится из наличия показов. Все 12 URL без показов инспектированы.
- `mobileUsabilityResult` больше не возвращается Google (VERDICT_UNSPECIFIED); мобильное удобство не оценено.
- Цифры «262 проиндексировано / 78 исключено» — из документа 6 сентября (интерфейс GSC), в этом аудите не воспроизведены.

## Производительность

- Core Web Vitals не измерены: PageSpeed Insights API без ключа — «Quota exceeded» (общая анонимная квота); CrUX API требует ключ; локальный Lighthouse не установлен. Данные CrUX по домену, вероятно, недостаточны (документ 6 сентября).

## Публичный краул

- 289 URL из `sitemap.xml` + 18 URL из GSC вне sitemap проверены HTTP-запросами без выполнения JavaScript; структурированные данные извлечены из JSON-LD в HTML, но не валидированы Rich Results Test'ом. Пересечения `Service`/`ProfessionalService` в счётчиках `jsonld_has_service` — по подстроке (см. TECHNICAL_SEO.md).
- Краул сделан с UA аудита; персонализация/геозависимость выдачи не учитывались. Реальная выдача Узбекистана по контрольным запросам не снималась (нет SERP-инструмента в скоупе; OpenSEO-кредиты = 0).

## Классификация

- Кластеры, язык и интент — регулярные выражения (`analysis.py`), не ручная разметка. Пограничные случаи: «chatgpt uz» отнесён к нейтральному языку; фонетические «jaji piti / chachipiti / жажипити» — к узбекскому; «gpt bot» (15 показов) — к бренду. «other» — 137 запросов (353 показа), не классифицированы.
- Ожидаемый CTR — медиана самого сайта по диапазонам позиций (n ≥ 60 показов); для диапазонов 1–3 и 11–20 выборка недостаточна.

## Предположения

- Рост с конца августа объяснён совокупностью: улучшение позиций download-статьи, публикация login-статьи 1 сентября, сезон (учебный год). Причинность не доказана.
- Потенциал кликов в quick wins — арифметика «показы × (медиана − текущий CTR)» при неизменной позиции; не прогноз.
- Услуги, на которые опираются рекомендации, взяты из `content/pages` и `site.json` (цены, Telegram-CTA); их актуальность подтверждает владелец.

## Что не менялось

Production, DNS, GSC-настройки, sitemap-submissions, canonical, robots — без изменений. Ветка `seo/gsc-audit-20260917` содержит только `docs/seo/gsc-audit-2026-09-17/` и `seo-audit/gsc-2026-09-17/`; секретов в файлах нет (токен читается из хранилища Claude Code во время выполнения и не сохраняется).

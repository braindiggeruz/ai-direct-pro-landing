## 1. Хлебные крошки: откуда «Unnamed item» и что с ним делать

### 1.1 Причина

В URL Inspection Google подписывает найденный элемент разметки его свойством `name`. Объект `BreadcrumbList` до 24.10 состоял только из `@type` и `itemListElement`. У каждого `ListItem` имя и абсолютный адрес есть, поэтому вердикт PASS и это не ошибка (L4 §5).

Где собирается разметка [REPO]:

|---|---|---|
| `scripts/jsonld-helpers.ts` `buildBreadcrumbLd()` | 234–246; исключение защищённых — 211 и 236 | общий построитель |
| `scripts/prerender.ts` | 368–371 | все content-страницы, оба чата |
| `scripts/prerender-blog.ts` | 290 (статьи), 567 (индексы блога) | статьи, `/ru/blog/`, `/uz/blog/` |
| `apps/studio/scripts/studio-page.ts` | 353 | студия |

Сейчас в сборке [DIST]: 326 страниц с `BreadcrumbList`, у 317 есть `name`, у 9 нет. Эти 9 — ровно `PROTECTED_PATHS` без `/` (`scripts/seo-protection.ts:210-219`). Ещё у 2 страниц (`/`, `/uz/`) списка нет: у `/uz/` его убрали, потому что крошка вела сама на себя. Тест — `tests/seo-breadcrumb-ld.test.ts`.

**Нет.** Крошки и так проходят проверку (PASS). На мобильных Google с января 2025 г. вообще не показывает крошки в результатах, только домен. Значит, ожидаемый эффект в кликах ≈0. Правку стоит сделать для порядка, но приоритет у неё самый низкий.

### 1.4 Исправление для 9 защищённых страниц

- **Файл.** `scripts/jsonld-helpers.ts:236`. Вместо всего `PROTECTED_PAGES` держать без имени отдельное множество `BREADCRUMB_NAME_HELD`, и с каждой ревизией его сокращать:

- **Тест.** В `tests/seo-breadcrumb-ld.test.ts:34` и `:52` вместо «защищённые без имени» проверять «без имени только страницы из `BREADCRUMB_NAME_HELD`». Когда множество пустое — «у всех 326 есть name».
- **Ревизия.** Строка `invisibleToGate` «BreadcrumbList gains top-level name on N protected pages». `seoContract()` вырезает `<script>` (`scripts/seo-protection.ts:231-249`), поэтому гейт эту правку не заметит, и её нужно записать явно.

### 2.2 Почему по узбекским запросам показывается RU-чат

Hreflang говорит Google: «это одна страница на двух языках, показывай ту, что совпадает с языком пользователя». В Узбекистане интерфейс Google по умолчанию русский (`01-data-truth.md` §0 п.4). Поэтому по «chatgpt kirish», «chatgpt bepul», «chatgpt uzbekcha» часть показов уходит RU-чату. По дням доля RU-чата по «chatgpt kirish» прыгает от 0 до 99 % (`03-ru-phonetic-cluster.md` §1.3). Механизм — **UNVERIFIED**, но цифры с ним согласуются. Цена ≈30 кликов за 28 дней (там же).

Что из этого следует:
- **Пару чатов оставить.** Продукт один, а без hreflang RU-чат всё равно ранжируется по узбекским словам: на нём узбекский первый абзац и ссылки. Тогда две страницы просто конкурировали бы без подсказки. Обе страницы защищены, и любая правка head ломает окно 24.10.
- **Не делать hreflang с кодом региона** (`ru-UZ`). У RU-чата около 60 % показов приходится не на Узбекистан (94 001 всего против 37 912 UZ, [GSC-28]). Код региона только запутает выбор версии, а регион у сайта и так задан доменом `.uz` — это национальный домен Узбекистана, Google привязывает его к стране автоматически.
- **Новое правило (Т-05): не связывать hreflang узбекские гайды по скачиванию и входу с будущими RU-страницами.** У гайда по скачиванию единственный ТОП-3 сайта («chatgpt yuklab olish uzbek tilida», 2,6; CTR 3,7 %, в зоне риска). Если появится RU-версия («скачать ChatGPT», запрос «chatgpt uzbekcha скачать» есть в отчёте) и её свяжут hreflang, пользователи с русским интерфейсом начнут получать RU-страницу по узбекскому запросу — ровно как с чатами. Делать RU-гайд как самостоятельную страницу с перекрёстной ссылкой, без hreflang. Записать решение в `intent-manifest.json`.
- `og:locale` `ru_RU` / `uz_UZ` Google для выбора языка не использует. Не трогать.

## 10. Ограничения

- Граф ссылок построен по пререндеренному HTML. Ссылки, которые React добавляет после монтирования, не видны. Зоны определены по тегам; карточки — по `data-testid`.
- Показы [GSC-28] взяты из выгрузок 24.09–21.10. Окно отчёта — 27.09–24.10, сдвиг 3 дня. Срез Узбекистана содержит только строки страниц, без анонимизированного хвоста.
- LCP и CLS — лаборатория на одной машине, 2 прогона. Первый прогон дал выброс на холодном старте. Поля нет.
- Утверждения о правилах Google — по документации и объявлениям Google Search Central, сегодня не перепроверял:
  - FAQ — только государственные и медицинские сайты (2023);
  - HowTo убран (2023);
  - крошки на мобильных не показываются (январь 2025);
  - для сниппета приложения нужен рейтинг;
  - видео-сниппет — для страниц, где видео главное.
- Яндекс: состояние Вебмастера, регион и индекс не видны. Всё про Яндекс — со слов владельца и по GA4 (L4 §9).
- Связь «hreflang + русский интерфейс → показ RU-чата» — **UNVERIFIED** как механизм. Её подтверждают дневные доли (`03` §1.3) и живые проверки с телефона (`01` §0 п.4).

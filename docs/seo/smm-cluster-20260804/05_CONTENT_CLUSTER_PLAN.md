# 05. План кластера

**Дата:** 2026-08-04. Кластер `smm-ru`.

## Архитектура

```
                    /ru/smm-prodvizhenie-tashkent/   ← HUB (money, Service schema)
                    «SMM-услуги в Ташкенте»            существующая, усилена
                              ▲
        ┌─────────────────────┼─────────────────────┬──────────────────────┐
        │                     │                     │                      │
  chto-takoe-smm-      stoimost-i-pakety-    chto-vhodit-v-        dogovor-na-okazanie-
  prodvizhenie/        smm-uslug-v-          uslugi-smm-           smm-uslug-v-
  (существующая)       tashkente/  ★НОВАЯ    specialista/ ★НОВАЯ   uzbekistane/ ★НОВАЯ
  «что это такое»      «сколько и за что»    «что делает           «как оформить»
                                              исполнитель»
```

Четыре spoke, один hub. Все в локали `/ru/`. Ни один spoke не является коммерческой страницей — значит `demand-gate` (он применяется только к `pageType: money|niche`) к ним не применяется, и ни одна новая страница не проходит мимо гейта спроса нелегально.

## Почему именно три новые страницы, а не пять

Постановка допускала до пяти. Отброшены две:

- **Instagram-страница** — каннибализировала бы hub (см. `04`).
- **UZ-latin версия** — интент по узбекским запросам смещён в вакансии и каталоги, точных данных об объёме нет (0 кредитов OpenSEO). Слабая страница ради количества URL противоречит и постановке, и `demand-policy.json`.

Минимальный порог из постановки («одна коммерческая + две supporting») выполнен и превышен: коммерческая усилена + три supporting.

## Оценка возможности (Opportunity Score)

Шкала 1–5 по каждому критерию, это **экспертная оценка на основе структуры выдачи**, а не измерение.

| Критерий | Цена и пакеты | Состав услуг | Договор |
|---|---|---|---|
| Разрыв в выдаче | 4 | 4 | **5** |
| Локальный коммерческий intent | **5** | 4 | 3 |
| Business fit | **5** | **5** | 3 |
| Можем дать лучший ответ | 4 | 4 | **5** |
| Конверсионная ценность | **5** | 4 | 3 |
| Отсутствие каннибализации | 4 | 3 | **5** |
| Скорость возможной индексации | 3 | 3 | 4 |
| **Итого** | **30** | **27** | **28** |

Все три выше порога. Порядок публикации значения не имеет — выходят одним коммитом.

## Роль каждой страницы в воронке

| Страница | Стадия осознания | Что читатель делает дальше |
|---|---|---|
| Договор | Решение принято, оформляет сделку | Проверяет своего подрядчика → или ищет нового → hub |
| Состав услуг | Сравнивает подрядчиков | Идёт считать бюджет → spoke «цена» → hub |
| Цена и пакеты | Формирует бюджет | Запрашивает расчёт → hub |
| Что такое SMM | Только разбирается | Идёт вглубь → любой из трёх → hub |
| Hub | Готов обсуждать | Telegram / заявка |

Воронка из постановки задачи («локальный запрос → полезный ответ → доверие → pillar → заявка») реализуется буквально: каждая статья имеет минимум одну контекстную ссылку на hub и CTA, соответствующий стадии.

## Что НЕ делается

- Не создаётся второй content engine — используются существующие `BlogArticle`, `BodyBlock`, prerender, sitemap-glob.
- Не меняется дизайн — статьи рендерятся существующим шаблоном.
- Не трогаются Bormi, marketplace, admin, API, миграции, Cloudflare, D1.
- Не выдумываются кейсы, клиенты, сотрудники, отзывы, сертификаты.
- Не публикуется собственный прайс — у GPTBot.uz нет опубликованного публичного прайса на SMM, и придумывать его нельзя (см. OFFER_TRUTH_GATE в `11`).
- Не добавляются схемы `Offer`, `Review`, `AggregateRating` — тест `no cluster document fabricates reviews or ratings` их прямо запрещает, и стоящих за ними данных нет.

## UZ roadmap (не выполняется сейчас)

Условия, при которых стоит вернуться к узбекоязычной версии:

1. Получен доступ к платному keyword-инструменту и измерен объём по `SMM xizmatlari`, `ijtimoiy tarmoqlarni yuritish`, `Instagram yuritish narxi` для location 2860.
2. RU-кластер набрал показы в GSC — подтверждено, что тема вообще приносит трафик домену.
3. Найдена формулировка с покупательским, а не соискательским интентом. `smm mutaxassisi` для этого не годится: топ занят вакансиями.
4. Есть готовность писать по-узбекски содержательно, а не переводить. Обязательно соблюдение апострофов U+2018 для `o‘`/`g‘` и U+2019 для тутук белгиси — это машинно проверяется тестом `Uzbek cluster copy uses the correct apostrophes`.

Приоритетный кандидат на первую UZ-страницу — **не** перевод одной из трёх, а `Instagram yuritish` / ведение аккаунта, потому что это единственная формулировка с явным сервисным, а не карьерным интентом.

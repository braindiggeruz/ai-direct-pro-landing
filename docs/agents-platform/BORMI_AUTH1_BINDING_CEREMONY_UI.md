# Bormi AUTH-1F — пользовательский слой привязки

Дополняет [BORMI_OWNER_TELEGRAM_BINDING_SECURITY.md](BORMI_OWNER_TELEGRAM_BINDING_SECURITY.md),
который описывает серверный протокол. Здесь — две поверхности, через которые
человек этот протокол проходит, и почему они устроены именно так.

Серверный протокол AUTH-1 не менялся. Добавлен один read-only endpoint (§3) и
одно presentation-поле в bootstrap (§6).

---

## 1. Чего не должно быть

До AUTH-1F привязку нельзя было выполнить вообще: endpoint существовал, а
дотянуться до него можно было только через DevTools или curl с admin-токеном в
руках. Это не «неудобно» — это небезопасно. Человек, которого просят достать
bearer-токен из консоли, учится делать ровно то, чему его обычно учат не делать.

Поэтому ни один шаг ниже не требует DevTools, SQL, curl, ручного Telegram ID или
извлечения session token.

## 2. Владелец: карточка в Owner Control Center

`src/admin/components/SellerBindingCard.tsx`, на странице магазина.

```
Привязка Telegram
  [Создать одноразовый код]
    → подтверждение: «Код даст этому Telegram доступ владельца
       к товарам и заказам магазина. Не пересылайте его другим людям.»
    → код, сгруппированный по 8 символов
    → [Скопировать код]  [Закрыть]  Действует ещё 9:47
    → 1. Откройте Mini App со своего Telegram
       2. Кабинет → Настройки и помощь → Привязать магазин
       3. Вставьте код и подтвердите
```

Вызов `ownerApi.createSellerBindingChallenge()` **не принимает аргументов**.
Магазин определяется на сервере из авторизации самого владельца; поля, которым
можно было бы указать на другой магазин, здесь просто нет.

### Где живёт код

Только в React state. Не в `localStorage`, не в `sessionStorage`, не в URL, не в
логах, не во второй копии где-либо ещё. Сервер хранит только SHA-256, поэтому
закрытие карточки уничтожает значение окончательно — восстановить его не может
никто, включая нас. Кнопка «Скопировать» кладёт в буфер **исходную строку**;
группировка по 8 символов существует только для глаз.

Состояния: выключено (сервер ответил `not_found` — действие блокируется), уже
есть живой код (`challenge_exists`), магазина нет (`store_unavailable`), магазинов
больше одного (`store_ambiguous`), слишком часто (`rate_limited`), общая ошибка.
Admin-токен не читается, не показывается и не копируется — он остаётся внутри
общего owner API client.

## 3. Решение по inspect endpoint

§10 задания требовало выбрать: read-only проверка кода или один submit.

Выбран вариант **A** — `POST /identity/seller-binding/inspect`.

Причина: погашение необратимо, а подтверждение, которое ничего не называет, —
не подтверждение. Экран, спрашивающий «привязать этот Telegram?», обязан уметь
сказать **к чему**, и endpoint погашения для этого использовать нельзя: он
потратит код, чтобы нарисовать диалог.

Почему это не опасный oracle:

- требует проверенной Telegram-сессии — анонимно недостижим;
- закрыт тем же флагом;
- пространство подбора 2^256;
- ничего не записывает и не помечает использованным;
- возвращает ровно одну строку — отображаемое имя магазина, которое владелец
  уже видел при выпуске кода;
- те же проверки TTL/scope/использования/статуса магазина, что и у погашения;
- **собственный лимит попыток**, поэтому частые проверки не тратят попытки,
  нужные для самой привязки;
- все отказы схлопнуты в тот же `validation_failed`, что и у погашения.

## 4. Telegram: экран погашения

`apps/market-mini-app/src/screens/SellerBindingRedeem.tsx`, lazy-чанк.

```
‹ Настройки и помощь
Привязать магазин

Введите одноразовый код из кабинета владельца.

[ Bir martalik kod / Одноразовый код ]
Код срабатывает один раз. Не пересылайте его другим людям.
[Очистить]

[ Проверить код ]
   ↓
Магазин            Bormi Demo
Доступ             Товары · Заказы · Вопросы · Остатки

[ Привязать этот Telegram ]
[ Отменить ]
```

Привязывается `claims.sub` — субъект сессии, построенной из подписанного
Telegram `initData`. В теле обоих запросов ровно одно поле: `challenge`. Ни
identity, ни organization, ни store клиент не передаёт и передать не может.

## 5. Формат кода

64 hex-символа. Перед отправкой убираются только разделители, которые мог
внести показ (пробелы, дефисы), и приводится регистр:

```ts
raw.replace(/[\s-]+/g, '').toLowerCase()
```

Ничего не подставляется, не достраивается и не сокращается. `O` не превращается
в `0`, `l` не превращается в `1`: код, потерявший энтропию из-за услужливого
автокорректора, — код, которым уже ничего нельзя доказать. Код с потерянным
символом остаётся неверным, и это правильно.

Показывается открытым текстом моноширинным шрифтом — владелец должен видеть, что
вставил именно то, что копировал. Маскировать точками нельзя.

## 6. Флаг и видимость

`MARKET_OWNER_TELEGRAM_BINDING_ENABLED` — единственная власть; оба endpoint
перечитывают его на каждом вызове.

`flags.ownerTelegramBinding` в bootstrap — **presentation only**: решает,
показывать ли строку в Кабинете. Additive и optional, поэтому запуск, отвеченный
до этого релиза, просто не имеет такой строки. Клиент, выставивший поле руками,
упирается в тот же 404.

Строка показывается при `bindingOffered && !sellerAvailable`: у кого магазин уже
есть, тому привязывать нечего.

## 7. Навигация

Порядок Back: подтверждение → экран привязки → Настройки и помощь → Кабинет.

Аппаратная кнопка Android, Telegram BackButton и видимый «Назад» используют один
контракт QP-0. Back во время записи отклоняется, чтобы не оставить
наполовину отвеченный вызов. Из экрана привязки Back никогда не закрывает Mini
App. Введённый код при уходе назад стирается — вставить его заново дешевле, чем
хранить.

## 8. Доступность и локализация

RU и узбекский латиницей, полная пара для всех 26 ключей. Апостроф —
U+2018/U+2019 по конвенции проекта, ASCII-апостроф запрещён и проверяется тестом.
Microcopy не упоминает membership, identity, organization, sellerCommands,
provider или audit: человек привязывает магазин, а не строку в таблице.

Проверено на работающем приложении: `<label>` оборачивает поле, подсказка внутри
него, ошибка объявляется через `role="alert"`, статус — через `role="status"`,
фокус переводится на поле при открытии и на статус при ошибке, ни одной цели
меньше 44 px, горизонтальной прокрутки на 320 px нет.

## 9. Что запрещено и проверяется тестами

Код не попадает в URL, query, hash, Telegram start parameter, историю,
`localStorage`, `sessionStorage`, логи, аналитику или crash-репорты. Ни одна из
двух поверхностей не содержит `console.*`. Проверено и статически, и на живом
приложении (`localStorage` пуст, URL без кода на каждом шаге).

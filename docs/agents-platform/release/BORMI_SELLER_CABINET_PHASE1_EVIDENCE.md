## 1. Что сделано

Реализованы фазы 1 (фундамент кабинета) и 3 (редактор товара v2) из
[roadmap](../BORMI_SELLER_CABINET_ROADMAP_2026-08-02.md). Фазы 2, 4, 5, 6 (медиа R2,
AI-студия, публичный каталог, настройки магазина) не начинались — они требуют
новой инфраструктуры, новых миграций и отдельных owner-гейтов.

### 1.1. Сервер

| Изменение | Файл | Почему |
|---|---|---|
| Потолок очереди заказов 5 → 50 | `agents/sotuvchi/orders/validation.ts` | продавец не мог увидеть шестой заказ дня |
| Keyset-пагинация `listOrderPage` | `agents/sotuvchi/orders/service.ts` | `nextCursor` был всегда `null` |
| Фильтр по статусу в SQL | `agents/sotuvchi/orders/store.ts` | статус выводится из пары `status` + `fulfillment_status`; фильтр читает обе половины |
| Курсор как непрозрачная строка | `agents/sotuvchi/orders/validation.ts` | внутри нет ни магазина, ни личности, ни смещения |
| Лимит листинга каталога владельца до 100 | `agents/sotuvchi/catalog/validation.ts` | покупательская выдача остаётся на 20 |
| `GET /seller/overview` | `market/router.ts` | exception-first домашний экран |
| `owner`-блок в seller-DTO | `market/router.ts` | `searchTerms` и двуязычные метки — только на `/seller/*` |

Новые публичные символы: `listOrderPage`, `encodeSellerOrderCursor`,
`requireSellerOrderCursor`, `requireSellerStatusFilter`, `requireCatalogOwnerLimit`,
`SellerOrderPage`, `SellerOrderListQuery`, `SellerOrderCursor`.

Существующий `listOrders` (массив, дефолт 5) оставлен без изменений — на нём
живёт бот-поток и старые вызовы.

### 1.2. Клиент

`apps/market-mini-app/src/screens/SellerApp.tsx` переписан целиком.

**Новая навигация:** Сегодня · Заказы · Товары · Вопросы · Остатки.

**Экран «Сегодня»** — только то, что требует действия, в порядке срочности:
новые заказы (с возрастом), заказы старше SLA (24 ч), вопросы без ответа,
опубликованные товары без остатка, неопубликованные черновики, слабые карточки.
Пустые группы не рендерятся. Когда всё чисто — «Всё разобрано» и кнопка добавить товар.

**Заказы:** сегменты Все/Новые/Подтверждён/Выполнен/Отменён, `useInfiniteQuery`
по курсору, кнопка «Показать ещё». В детали заказа добавлен предпросмотр остатка
после подтверждения (`8 → 6`).

**Товары:** сегменты по статусу, поиск по названию, значок «Слабая карточка».

**Редактор товара v2:** характеристики (RU/UZ метки + значение, ключ генерируется
транслитерацией под доменный паттерн `[a-z][a-z0-9_]{0,31}`), поисковые слова
(чипы, до 12), цена с живым форматированием («349 000 сум · Проверьте разряды»),
предпросмотр карточки глазами покупателя.

**Конфликт версий (409)** больше не голая строка: баннер объясняет, что запись
изменилась, сам перечитывает её и сохраняет введённое. Подключён ко всем пяти
мутациям с версией: заказ, ответ на вопрос, сохранение товара, публикация, остаток.

### 1.3. Мёртвый капитал, который ожил

`searchTerms` и `specifications` существуют с миграции `0027` и участвуют в
ранжировании поиска, но заполнить их из интерфейса было нельзя — у всех товаров
они пустые. Теперь они редактируются. Изменений схемы не потребовалось: сервис
каталога уже валидировал оба поля на create и update.

## 4. Откат

Кода в проде нет — откатывать нечего. После деплоя:

1. Root/BFF откатывается на предыдущий deployment (текущий immediate rollback —
   `e3aa4b9a-...`, source `e4669b7`; полные ID подтвердить в Cloudflare);
2. статический Mini App откатывается отдельно от бэкенда;
3. D1 не откатывается — он не менялся;
4. после отката: `/start`, открытие Mini App, текстовый поиск, каталог, bot fallback,
   read-only агрегаты D1, проверка webhook.

Отдельный флаг для кабинета не заводился: изменение не добавляет новых
возможностей за пределами существующего `MARKET_MINI_APP_SELLER_COMMANDS_ENABLED`,
а откат покрывается заменой статического деплоя.

## 5. Что не доказано

- поведение на реальном магазине с сотнями заказов — фикстура держит единицы;
- реакция реального продавца на новый экран «Сегодня»;
- SLA в 24 часа выбран как разумный дефолт, а не измерен;
- порог «слабой карточки» (нет фото / описания / характеристик / поисковых слов)
  не подтверждён данными о том, что именно проседает в поиске;
- влияние заполненных `searchTerms` на долю нулевых результатов будет видно
  только после того, как продавец их заполнит;
- нативная проверка в Telegram на устройстве владельца не выполнялась.

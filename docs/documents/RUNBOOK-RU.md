# Облачные PDF GPTBot.uz — эксплуатация

Рабочая интеграция выпущена 07.11.2026. Это отдельный обработчик PDF; текущие сайт, чат, AI-провайдеры, платежи и SEO обслуживаются прежним Cloudflare-приложением.

## Использование

- Владелец: https://gptbot.uz/admin-tools/documents — существующий вход владельца, компания/задача/состав работ/согласованные условия, язык разделов RU или UZ, создание и скачивание PDF.
- Презентации: https://gptbot.uz/ru/prezentatsiya-ai/ и https://gptbot.uz/uz/taqdimot-ai/. После результата доступен облачный PDF; «Мои облачные PDF» открывает историю по явному нажатию.
- В чате тот же экспорт доступен в рабочей области готовой презентации. Существующий локальный PPTX сохранён.
- Экспорт переносит текст, заголовки, пункты и заметки. Иллюстрации и произвольные HTML-шаблоны не загружаются. Выбор языка не переводит введённый текст автоматически.
- PDF доступен 24 часа с создания задания. Очистка запускается каждую минуту; при недоступности worker физическое удаление откладывается до восстановления, но API закрывает скачивание по сроку независимо. Техническая запись без текста удаляется через 7 дней.
- Квоты запуска: 3 задания на подписанного пользователя в UTC-сутки, 20 на сайт; повтор с тем же Idempotency-Key не создаёт второе задание. После перезагрузки сначала проверить историю. Токены чата и баланс платных пакетов не списываются.

## Контроль и ограничения

`/healthz` — жив ли процесс, а не доказательство успешного PDF. Проверять события `document_completed`, долю failed, возраст queued, очередь D1 и фактический PDF. Логи не содержат текста документов или ключей. Метрика nodeRssBytes не включает Chromium; общий расход смотреть в Railway Metrics/Usage.

Снимок usage всего Railway workspace после запуска: $0.05857. Это не прогноз месяца. Hobby не означает безусловный потолок счета $5; глобальный hard limit не устанавливался, поскольку в workspace работают два других проекта. Квоты, память и число реплик ограничивают новую функцию. Не добавлять Postgres/Redis/n8n или постоянный браузер без измеренной необходимости.

Worker выходит в сеть только к заданному HTTPS origin, без редиректов. Рендер принимает ограниченный структурированный текст, экранирует его; JS и внешние запросы браузера отключены. У worker нет Railway account token, D1 credentials или пользовательских cookies. Для эксплуатации ему не нужен переданный в чате аккаунтный ключ Railway: его можно отозвать в кабинете после установки.

## Остановка / восстановление

При проблеме выключить только `DOCUMENT_JOBS_ENABLED` в двух согласованных формах runtime config и сделать guarded deploy. UI покажет недоступность, обычные презентации/PPTX и чат сохранят прежнее поведение. Согласованно остановить только новый Railway worker при необходимости; не менять общий бюджет/проекты. Не удалять таблицу, bucket и неопределённые результаты. Для возврата восстановить shared secret, binding, flag и проверить полный путь.

Не переключать старый `apps/gpt-backend`/Railway gateway: это другой backend. Не менять Click/OFD, Telegram webhook, текущие AI-тарифы и SEO ради документов.

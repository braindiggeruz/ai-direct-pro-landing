# Bormi Admin — модель безопасности

Дата: 2026-08-03.

## 1. Главное

Панель — это **клиент существующей защищённой поверхности**. Она не добавляет
ни одного нового способа получить права: ни аутентификации, ни регистрации, ни
второго backend, ни прямого доступа к D1.

```
BORMI_ADMIN_AUTH_REUSED=YES
BORMI_ADMIN_DIRECT_D1=NO
NEW_ADMIN_BACKEND=NO
PUBLIC_SIGNUP=NO
```

## 2. Аутентификация

Сессия — та же, что у прежнего Owner Control Center: bearer-токен в
`localStorage` под ключом `gptbot_admin_token`, на том же origin. Панель его
**читает** и отправляет в заголовке `Authorization`. Она его не создаёт, не
обновляет, не дублирует под своим ключом, не пишет в URL и не логирует.

Формы входа в панели нет. Нет токена — браузер уходит на `/admin-tools/login`,
который и владеет сессиями. 401 от любого запроса — туда же.

Это же решение определило топологию: панель живёт на том же origin, что и API.
Отдельный домен потребовал бы CORS на admin-эндпоинтах и второй способ передать
сессию — то есть расширение поверхности атаки ради косметики.

## 3. Авторизация

Решает сервер, на каждом запросе:

- `requirePlatformRole` — единственная точка проверки роли, не изменялась;
- `GET /api/admin/overview` — `withOwnerRole('platform_owner')`;
- `/api/admin/agents/stores`, `/agents/audit` — как были (`support_readonly` и выше).

Клиент:

- маршрут — не полномочие; скрытая кнопка — не защита;
- `hasSession()` решает только, показывать ли экран или отправить на логин;
- `rollout.admin_v2` приходит **с сервера** и решает, рисовать ли панель;
- 403 показывает «недостаточно прав» и ничего не пытается обойти.

Ролей ровно две — `platform_owner` и `support_readonly`. Панель в первом срезе
рассчитана на владельца: главный endpoint требует owner. Будущие роли
(модератор, операции) не захардкожены в обход — они добавляются на сервере, а
навигация строится из списка, а не из `if` по роли.

## 4. Что панель не делает

| запрещено | статус |
|---|---|
| Прямой доступ к D1 из браузера | нет ни одного упоминания D1 в клиенте |
| Свой backend рядом с существующим | не создан; один новый endpoint живёт в том же Functions-приложении и использует тот же guard |
| Запись | в ADMIN-1/2 нет ни одного POST/PUT/PATCH/DELETE |
| Редактирование аудита | невозможно: таблица append-only, endpoint только `GET` |
| Переключение feature flags | только чтение; изменение — коммит `wrangler.toml` + деплой |
| Импersonation | нет |
| Показ секретов | не читаются и не передаются |
| Показ PII | Telegram ID, username, телефон, адрес, initData и текст сообщений не запрашиваются ни одним экраном |
| Показ кода привязки | панель показывает только состояние церемонии (открыта/закрыта, сколько кодов), никогда сам код и не его хэш |
| Ослабление AUTH-1F | контракт не тронут: mint и redeem остались там же и с теми же проверками |

## 5. HTTP

| механизм | решение |
|---|---|
| `noindex, nofollow, noarchive` | meta в `index.html`; `/admin/` добавляется в `robots.txt` вместе с `/admin-tools/` при выкладке |
| Кэш ответов API | клиент запрашивает с `cache: 'no-store'`; ответы owner-эндпоинтов уже отдаются как приватные |
| Кэш HTML-оболочки | статический бандл с хэшами в именах — обычная иммутабельная выдача |
| CORS | не нужен: тот же origin |
| CSRF | токен в заголовке, не в cookie; браузер не отправляет его автоматически с чужого сайта |
| Токен в URL | не встречается ни разу |
| Логи | ни одного `console.*` в бандле панели |
| Заголовки безопасности | берутся из общего `_headers` root-проекта; отдельная запись для `/admin/*` добавляется на этапе выкладки |

## 6. Rollout flag

```
BORMI_ADMIN_V2_ENABLED = "false"
```

Presentation-only. Он не даёт прав и не открывает эндпоинтов: сервер их
проверяет одинаково при любом значении. Выключенный флаг означает, что панель
отказывается рисовать себя и показывает ссылку на прежнюю консоль. Откат —
вернуть `false` и задеплоить root.

## 7. Что осталось на потом

- **ADMIN-8** (записывающие действия) потребует: подтверждение, типизированное
  подтверждение для опасных операций, причина, идемпотентность, запись в аудит.
  Ни одного из них не нужно сейчас, потому что записей нет.
- Заголовок `Cache-Control: no-store` для `/admin/*` в `_headers` — вместе с
  первой выкладкой.
- `robots.txt`: добавить `/admin/` в общий disallow — там же.

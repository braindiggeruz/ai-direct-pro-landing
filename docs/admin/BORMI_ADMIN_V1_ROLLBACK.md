# Bormi Admin v1 — откат

Что откатывается по-разному, в порядке от самого дешёвого к самому дорогому.

---

## 1. Выключить панель (секунды, ничего не теряется)

```
BORMI_ADMIN_V2_ENABLED = "false"
```

Панель собрана и задеплоена, но `App.tsx` показывает экран «Bormi Admin
выключен» со ссылкой на прежнюю консоль. Прежний Owner Control Center
(`/admin-tools/*`) продолжает работать: ADMIN-4A встал рядом с его endpoint'ами,
а не поверх них.

Флаг — это коммит в `wrangler.toml`, а не правка в дашборде.

**Чего это не делает:** не откатывает уже выполненные переходы объявлений и не
удаляет строки аудита. Так и должно быть.

---

## 2. Откатить деплой (минуты)

Задеплоить предыдущий SHA. Вместе с ним уходит `functions/admin/[[path]].ts` и
запись `/admin/*` в `_routes.json`, поэтому `/admin/…` снова возвращает 404 —
что и есть состояние до v1. `robots.txt` и `_headers` генерируются сборкой,
поэтому откат сборки откатывает и их.

Порядок сборки при повторной выкатке обязателен:

```bash
npm run build
```

```bash
npm run build:admin
```

Обратный порядок сотрёт `dist/admin` корневой сборкой, и `/admin/` вернёт пустой
экран без единой ошибки в логе.

---

## 3. Откатить действие над объявлением (минуты)

Обратным доменным переходом:

* `publish` ↔ `unpublish`;
* `archive` — обратного перехода в домене каталога **нет**. Вернуть
  заархивированную карточку может только продавец, создав её заново.

Обратный переход тоже пишется в аудит: след остаётся полным.

---

## 4. Откатить миграцию 0033 — почти всегда неправильный ответ

Обратная пересборка `owner_audit_events` без трёх глаголов и без `product`
допустима **только пока ни одна строка их не использует**.

После первого аудированного действия над объявлением сужение CHECK либо упадёт
на копировании строк, либо потребует удалить именно ту строку, которая
фиксирует, что владелец сделал с объявлением продавца. **Удаление истории аудита
ради восстановления ограничения — не откат.**

Поэтому:

* если действий ещё не было — обратная миграция технически возможна, но и не
  нужна: расширенный CHECK ничему не мешает;
* если действия были — откатывается действие (раздел 3), а схема остаётся.

Полный текст этого решения — в комментарии внизу
`migrations/0033_owner_audit_listing_actions.sql` и в
[BORMI_ADMIN_AUDIT_ACTION_MIGRATION_REHEARSAL.md](BORMI_ADMIN_AUDIT_ACTION_MIGRATION_REHEARSAL.md).

---

## 5. Что откату не подлежит, потому что не менялось

* `AUTH-1F` — правила привязки продавца не трогались;
* QuickPost — все флаги остались `false`;
* Mini App — не изменялся;
* `/admin-tools/*` — прежняя консоль, её маршруты и её заголовки на месте;
* публичный сайт — глобальный блок заголовков, CSP и `X-Frame-Options:
  SAMEORIGIN` не изменялись; изменения касаются только `/admin/*`;
* `robots.txt` — добавлен один `Disallow: /admin/`; ни один публичный путь не
  закрыт;
* заказы, обращения, категории — ни один оператор ADMIN-4A в них не пишет.

---

## 6. Что сломается, если откатить частично

| Откачено | Оставлено | Что произойдёт |
| --- | --- | --- |
| миграция 0033 | код панели | команда отвечает `listing_transition_conflict` (409), объявление не двигается, в аудите ничего. Фейл закрытый и проверен тестом |
| код панели | миграция 0033 | ничего: расширенный CHECK просто не используется |
| `functions/admin/[[path]].ts` | `dist/admin` | `/admin/` отдаёт оболочку как статический файл, но подмаршруты 404, и заголовки — глобальные, без `no-store` |
| `dist/admin` | Function | Function отвечает 503 с внятным текстом, а не пустой страницей |

Вторая строка — причина, по которой порядок сборки в разделе 2 не
рекомендация: корневая сборка очищает `dist` целиком.

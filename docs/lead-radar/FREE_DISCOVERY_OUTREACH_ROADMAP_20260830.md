# Lead Radar — бесплатный discovery контактов и надёжная рассылка по нише (roadmap 2026-08-30)

База: аудит `docs/lead-radar/audit-2026-08-30/` (находки QR-*/DS-*/TG-*/CP-*). Этот документ отвечает на задачу владельца: улучшить парсинг Telegram-username'ов и телефонов, убрать платную зависимость (Firecrawl) и довести продукт до надёжного нишевого outreach-сервиса.

## 0. Принципы (не обсуждаем, они уже в коде продукта)

1. **Бесплатно** = собственная инфраструктура + публичные данные. Не «бесплатные обходы» Telegram.
2. Только публичные источники: сайты компаний, публичные каталоги, публичные страницы t.me. **Не скрейпим участников групп/каналов, не импортируем чужие контакт-листы, не обходим privacy.** GitHub-инструменты типа Telerecon/Telegradd (member scraping + adder) для этого продукта запрещены: это нарушение privacy и прямой путь к бану аккаунта-отправителя.
3. «Идеально работает» = предсказуемо и честно: монотонный прогресс, ни одна компания не теряется молча, у каждого исключения есть причина, у каждого подтверждения — доказательство. Это не обещание «Telegram у 100% стоматологий» — у части ниши его физически нет, и правильное поведение — объяснить, а не догадаться.
4. Все гейты аудита остаются: strict Bridge verification, DNC, authorization, pacing 30/день + 120 с. Это не бюрократия, а то, что удерживает аккаунт живым.

## 2. Целевая бесплатная архитектура discovery (4 уровня)

```text
Компания (OSM Overpass — уже бесплатно)
  │
  ├─ TIER 0 · Worker, прямой fetch, бесплатно, всегда:
  │    официальный сайт → sitemap.xml → /contacts|/kontakt|/aloqa|/about
  │    → JSON-LD + tel: + t.me/tg:// (существующий экстрактор)
  │    + t.me/<username> pre-check (существует/тип по title/description)
  │
  ├─ TIER 1 · Worker, прямые HTML-скрейперы каталогов (те же 9 UZ-каталогов,
  │    но по своим URL-шаблонам поиска, без Firecrawl search; robots соблюдаем)
  │    + trafilatura-очистка грязных карточек
  │
  ├─ TIER 2 · Локальный runner (отдельный venv, НЕ venv Bridge):
  │    Scrapling (stealth/browser) для 403/JS-страниц + каталогов,
  │    забирает задачи из очереди job'ов (lease/backoff — уже есть в D1)
  │    работает, когда ПК включён; офлайн → jobs паркуюсь resumable
  │
  └─ TIER 3 · SearXNG self-host (Docker): поиск официального сайта
       и «имя + t.me» только для no_website-компаний (малая доля)
       → далее снова Tier 0/2 для скачивания

Строгая верификация (без изменений, бесплатно):
  Bridge MTProto resolve → bridge_resolved_corporate / manual tier (B1)
```

Firecrawl остаётся опциональным платным fallback (флаг выключен — код уже поддерживает), но перестаёт быть обязательным звеном: сегодня без него контактная фаза стоит (`contact-source-worker.ts:13-14`, аудит DS-1).

## 3. Этапы

### R0 · Починка runtime (без него всё новое молча теряется) — 0 кода + 3 точки
- Деплой automation Worker на HEAD (QR-2/QR-3 из аудита: пул больше не замерзает, transient-сбои переживают backoff 15м/1ч/4ч).
- A1: возрождение contact-resolution job после dead letter (иначе любая пауза >30 мин = потерянная компания навсегда).
- C1: lease отправки 120с→180с; C2: реконсиляция sent/effect.
- **Приёмка**: поиск с припаркованным бюджетом пополняется; «остановить/запустить ПК» не убивает компании. Разрешение: production-деплой.

### R1 · Tier 0: бесплатный прямого-fetch extraction (Worker) — главный прирост, ~2-3 дня
- `enrichCompanyWebsiteDetailed` (functions/platform/lead-radar/sources.ts) расширить: после главной страницы — sitemap.xml и топ-кандидаты contact-страниц (уже есть ранжирование `selectFirecrawlContactPages` в firecrawl-enrichment.ts:103-106 — вынести в общий бесплатный путь), лимит 3-4 страницы/компанию, robots/safePublicHttpUrl как сейчас.
- Каталоги: прямые скрейперы карточек (yellowpages.uz/32top.uz/top.uz/...) по своим URL-шаблонам вместо Firecrawl search: запрос «niche+city» → карточки → (сайт, телефоны, t.me). Один модуль `catalog-scrapers.ts` с адаптером на каталог + graceful degrade при смене вёрстки (это то, чему помогает Scrapling self-healing на Tier 2).
- t.me pre-check: `fetchPublicTelegramProfile(username)` — GET t.me/<username>, парсинг `tgme_page_title/description` (код уже есть в public-contact-discovery.ts:61-71) — бесплатная фильтрация до Bridge.
- **Приёмка**: на золотом наборе 30 компаний доля компаний с ≥1 lookup-eligible кандидатом растёт; ноль платных запросов.

### R2 · Tier 2: безопасный локальный runner (Scrapling) — 3-5 дней
- Реализовать обещанное из `UPGRADE_ROADMAP_SCRAPLING_20260829.md`: отдельный venv (не Bridge!), allowlist публичных таргетов, SSRF/DNS/redirect/size/time/concurrency-лимиты, никакой доступ к vault/сессиям Bridge.
- Транспорт: runner опрашивает D1-очередь job'ов (тип `source-fetch`), берёт lease (механизм lease/generation уже в store.ts), возвращает HTML в D1-кэш (TTL как сейчас 24ч); Worker продолжает экстракцию как обычно. Офлайн-ПК → job в resumable `waiting_for_runner` (после A1 это больше не смертельно).
- Сначала починить не пройденный JS-fixture бенчмарка — он и есть приёмка.
- **Приёмка**: 403/JS-страницы из золотого набора добираются; при выключенном ПК ничего не теряется.

### R3 · Tier 3: SearXNG — 1-2 дня
- Docker-контейнер на ПК владельца (рядом с Bridge, но отдельный сервис), `formats:[json]`, без ключа.
- Использование: только no_website-компании (поиск официального сайта — запрос уже есть `officialDomainSearchQuery`, official-domain-discovery.ts:41-45) и опционально `"имя" site:t.me`. Лимиты: ≤2 запроса/компанию, ≤50/день (D1-счётчик по образцу firecrawl-store).
- Замена base-URL: FirecrawlClient параметризуется env-переменной (сейчас хардкод api.firecrawl.dev, firecrawl-client.ts:145) — тот же код работает с самохостом, если когда-нибудь захотим.
- **Приёмка**: у ≥50% no_website-компаний из выборки появляется сайт-кандидат с identity-подтверждением; ноль затрат.

### R4 · Ownership manual tier — ключ к честному yield — 2-3 дня
- Каталожный username, который Bridge подтвердил как существующий, сегодня не считается (DS-2). Ввести ручное подтверждение оператором: карточка «проверить глазами и подтвердить владельца» → `reason='manually_confirmed_corporate'` + evidence(operator, время) → контакт входит в строгое множество только при активном authorization.
- Batch-действие в каталоге: «показать всех с подтверждённым существованием username» → оператор проходит список раз в неделю по 20-30 шт.
- **Приёмка**: contactTarget достижим для ниш, где сайт беднее каталога; в strict набор попадает только вручную подтверждённое.

### R5 · Рассылка «идеальна» в эксплуатации — 3-5 дней
- R5.1 Оптимизация кампаний по нише: шаблоны на нишу с `{company_name}` (уже), тестовый preview на 3 карточках (уже), A/B двух текстов с per-campaign счётчиками ответов.
- R5.2 Opt-out автоматом: входящее «стоп/не писать» на аккаунт → Bridge замечает в ledger → компания DNC автоматом (небольшой fan-in раз в час).
- R5.3 Отчёт недели по нише: компаний найдено → с контактом → подтверждено → отправлено → ответов → исключено и почему (знаменатели из аудита, QR-8 fix).
- R5.4 UX: подпись TTL верификации в каталоге (TG-1), сохранение draft текста (CP-3), UTF-16 лимит (CP-4).

### R6 · Масштаб после стабильности
- Повышение лимитов постепенно (30/день → 60) только после 2 недель без flood/жалоб; интервал не ниже 60-90 с; окна отправки в рабочие часы Ташкента.
- Никогда: member scraping, спам-боты, покупка «прогретых» аккаунтов, обход flood. Это не этика ради этики — Telegram банит аккаунт-отправитель, и сервис умирает.

## 4. Что остаётся платным / не тратим

- Ничего обязательного платного не остаётся: Tier 0-3 + Bridge покрывают полный цикл. Firecrawl API можно держать выключенным (fallback), SearXNG/scrapers — бесплатны, Bridge — свой аккаунт.
- Не тратим: прокси-пулы, SMS-верификации, «готовые базы», tgstat API.

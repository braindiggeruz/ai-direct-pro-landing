## Статус

Реализована локальная версия первого этапа: сбор с сохранённого официального
сайта компании → надёжная доставка результата → проверенные сервером сведения
в существующей карточке Lead Radar. Это не реализация всего roadmap и не
подтверждение production/send-ready. Функция по умолчанию выключена.

В этом этапе нет поиска компаний в новых каталогах, JavaScript-браузера,
массовой кнопки обогащения аудитории или автоматической отправки сообщений.
Найденный телефон/Telegram не означает возможность или разрешение отправки.

## Что добавлено

- Собственная очередь сборщика: исключение дублей, ограниченная аренда задания,
  поколение аренды, heartbeat, отмена, восстановление после остановки.
- Идемпотентные квитанции и единая транзакция квитанции, доказательств,
  следующего разрешённого времени источника и состояния задания.
- Полный `Retry-After` сохраняется; один недоступный домен не блокирует другой.
  Обычный `Crawl-delay` ожидается короткими интервалами в пределах срока задания,
  чтобы повторное чтение главной страницы не зацикливало контактную страницу.
- Локальный outbox отправляет те же сохранённые байты при потере ответа, а не
  повторяет сбор. После ACK тело очищается; неизвестные результаты старше семи
  суток помещаются в карантин, не объявляются принятыми.
- Выделенный токен сборщика ограничен организацией; сервер хранит только хеш.
  Секреты администратора и Telegram Bridge не используются.
- Сервер заново проверяет неизменность компании, запрет контакта, источник,
  время, хеш HTML и действующую аренду. Канонический TS-парсер формирует факты.
- Групповая запись фактов одним SQL-оператором: плотная фикстура с 60 фактами
  выполняет 11 запросов во всём authenticated result route, включая schema/auth;
  четыре оператора входят в атомарный batch.
- В подробной карточке компании в поиске появился отдельный блок сбора с сайта:
  запуск, ожидание источника, недоступный сборщик, частичный результат, отмена.
  Обновление находок не сбрасывает аудиторию и текст рассылки.

## Что именно использует Scrapling

Используется `Scrapling 0.4.15 Selector` для разбора HTML и поиска контактных
ссылок. Это не штатный Fetcher/Spider/StealthyFetcher и не обход блокировок.
Транспорт собственный: проверка всех DNS-ответов, привязка TCP к проверенному
публичному адресу, TLS/SNI исходного имени, контроль каждого redirect,
потоковые ограничения размера и времени. Cookies, прокси, платные API,
CAPTCHA-сервисы, LLM и Telegram-вызовы в сборщике отсутствуют.

Текущие границы: до пяти страниц за исполнение, 128 KiB на страницу,
512 KiB суммарного HTML, три redirect, 120 секунд исполнения, 180 секунд
аренды, до 12 попыток и 24 часов жизни задания. Строго один origin, поэтому
неподтверждённый переход `http→https` или на `www` не принимается автоматически.

## Важное ограничение перед включением: CPU

Приём HTML пока запускает полный канонический парсер в Pages request.
Офлайн Node/Windows benchmark на четырёх плотных контактных страницах показал
для суммарных 16/32/64/128 KiB средний warm process CPU
14.40/18.12/16.24/23.76 ms. Это не измерение Cloudflare: process CPU включает
все потоки, возможны GC/квантизация Windows, D1/auth/schema исключены.
Тем не менее эти результаты НЕ подтверждают безопасный бюджет бесплатного
сервера. Простое уменьшение размера HTML не считается решением: оно может
потерять footer и контакты, а холодный разбор остаётся дорогим.

Дополнительный замер отделил thread CPU от всех потоков процесса. Убрана только
неиспользуемая генерация sales signals/dates, НЕ проверки личных контактов.
На финальном коде `--components`, 50 warm повторов: 16/128 KiB дают
7.18/19.38 ms thread CPU (извлечение: 3.76/14.38 ms). Между прогонами есть
вариативность, доказанного ускорения этой небольшой оптимизацией нет. На
128 KiB остаётся риск CPU; искусственное прогревание кешей не решает cold-start.

Официальные границы: [Workers CPU](https://developers.cloudflare.com/workers/platform/limits/)
и [D1 queries](https://developers.cloudflare.com/d1/platform/limits/).
Групповая D1-запись уже устранила риск превышения 50 запросов.
Включение на production требует отдельного подтверждения CPU-бюджета либо
переноса тяжёлого канонического извлечения из request с сохранением границ
доверия и серверной проверки. Не повышать тариф и не включать платные провайдеры.

## Аварийная остановка / rollback

Выключить collector feature; остановить его изолированный запуск; отозвать
worker token и отменить задания (эти две owner-операции доступны и при
выключенном feature flag). Не удалять аудитории, основные таблицы, source
deadlines или историю рассылок. Additive-таблицы можно оставить: основной
schema guard исключает только четыре точных имени необязательной подсистемы.
Квитанции/сохранённые факты сохранять для разбора; до выяснения не повторять
неизвестный результат новым receipt ID.

# Подготовка рассылки: исправления 28 августа 2026

## Реализовано

- Ошибки подготовки/изображений показывают конкретный код, HTTP-статус и requestId. Отсутствующий файл, недоступный Bridge, схема и конфигурация больше не маскируются общей просьбой переподключить Telegram. Исходный requestId со старого скриншота не сохранился: точную причину именно того 404/503 задним числом не утверждаем.
- `/telegram-campaigns/preflight` проверяет готовность без создания кампании, разрешения, отправки или платного поиска: schema/key/routing/Bridge/account, ограничения запуска, активную кампанию, дневной остаток и получателей по настоящим основаниям. Для большого списка выполняются порции по 50.
- Короткая асинхронная проверка изображения: `/v1/media/check`, затем `/telegram-campaigns/media/check`. Операция повторно используется по tenant, immutable media, версии валидатора и UTC-дню. Старый синхронный маршрут оставлен для совместимости. Только подтверждённый `media_valid` регистрирует готовый файл в D1.
- После обновления вкладки восстанавливается ссылка на защищённый файл, не публичный URL и не байты. Проверка продолжается, доступна повторная проверка без перезагрузки файла. Локальное превью после обновления отсутствует; режим подписи и лимит 1024 символа сохраняются. Это не обещание восстановления несохранённого текста/выбора обычного поиска.
- Кнопка проверки Telegram у выбранных: публичные корпоративные мобильные/username, последовательные запросы с интервалом 3 секунды, DNC/личные/стационарные исключаются, FloodWait и недоступный Bridge останавливают цикл. Сервер хранит доказательства и квитанции, вкладка — только прогресс. Для продвижения списка вкладка должна оставаться открыта; после закрытия можно продолжить, завершённые компании пропускаются. Это ещё не независимый от браузера серверный batch scheduler.
- Готовность, карточки и верхний счётчик кампании используют один результат preflight. «Выбрать готовых на сервере» выбирает до 50 действительно авторизованных получателей, не все найденные телефоны. Серверные/аудиторные исключения могут только сузить список.
- Подготовка фиксирует именно подтверждённые server IDs; вторая проверка/подтверждение и отправка сохраняют прежние защиты от дублей, DNC, устаревших доказательств и неизвестной доставки. Реальные основания по-прежнему оформляются отдельно для каждой компании — фиктивное согласие не создаётся.

## Что ещё не доказано / не активировалось

- Первая реальная production-отправка: нужен конкретный согласованный тестовый получатель и точный текст (отдельно тест изображения). В этом выпуске сообщения не отправлялись и новые контактные lookup в production не запускались.
- Исторические ограничения Firecrawl не превращались в «нет Telegram». 126 старых limited, 2 unknown и 3 expired результатов не перезапускались; бюджет не повышался. Управляемое повторное обогащение и отдельный серверный batch scheduler остаются дальнейшими этапами дорожной карты, а не скрыто включёнными действиями.
- Групповое оформление реального документа, покрывающего несколько компаний, пока не добавлено. Действующая безопасная форма по одной компании сохранена.

## Порядок работы

Выбрать контакты → «Проверить Telegram у выбранных» → «Показать готовность на сервере» → устранить показанные причины/подтвердить реальное основание → обновить готовность → «Выбрать готовых на сервере» → проверить текст и изображение → «Проверить список и текст на сервере» → сверить все сообщения и отдельно подтвердить запуск.
